WordPress Core CVE-2026-87902: Unauthenticated Path Traversal Actively Exploited Within Hours of Patch
🔍 What happened: CISA added CVE-2026-87902 (CVSS 9.2), an unauthenticated path traversal vulnerability in WordPress Core, to its Known Exploited Vulnerabilities catalog on September 25 after threat actors began actively probing and exploiting unpatched sites within five hours of the patch release on September 22.
👤 Who's affected: Every WordPress website running versions 4.7.0 through 7.1.1 — nearly a decade of releases — representing tens of millions of sites globally, with no authentication required to trigger the flaw.
✅ What to do: Update to WordPress 7.1.2 immediately; verify in your hosting control panel that auto-updates completed, as attackers began mass scanning within hours of the public patch release.
🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
The flaw in WordPress's page-template resolver lets any unauthenticated attacker include arbitrary PHP files outside the theme directory, providing direct server-side code execution on unpatched WordPress installations without any account on the target site.
▶ Full analysis & beginner explanation
CVE-2026-87902 resides in WordPress Core's get_page_template() function. A specially crafted frontend HTTP request manipulates the template resolution path, causing WordPress to traverse outside its intended theme directories and include a readable PHP file elsewhere on the server — before any authentication check occurs. There is no barrier between an anonymous internet user and server-side code execution on vulnerable deployments.

The "conditional RCE" label means full remote code execution requires additional conditions: a readable PHP file must be accessible in the traversal path, and specific theme structure elements must be present. However, researchers found these conditions are commonly met in default hosting environments, making the theoretical restriction largely academic in real-world attacks. Patchstack observed active exploitation scanning within five hours of the September 22 public patch disclosure, and CISA's KEV addition on September 25 confirms in-the-wild exploitation is ongoing.

Security researcher Robert Ressl privately reported the bug via HackerOne on July 20, 2026. The two-month responsible disclosure period explains the patch timeline — but the near-instant weaponization after release underscores that unpatched sites are actively being compromised right now. Every version back to WordPress 4.7.0 is affected.
🎓 For beginners: Imagine a library where anyone can request a book just by knowing a shortcut path — no library card needed. This WordPress bug lets attackers give the server a special URL that tricks it into running a PHP script that was never meant to be publicly accessible. Because WordPress powers roughly 40% of all websites, even a vulnerability requiring certain conditions affects millions of sites simultaneously.

⚡ URGENT: WSO2 CVE-2026-5430 JWT Forgery Exploited Since Sept 13 — Federal Patch Deadline Is Tomorrow
🔍 What happened: CISA added CVE-2026-5430 (CVSS 9.8) — a critical JWT authentication bypass in WSO2 API management products — to its KEV catalog on September 24; forged JWT tokens targeting the flaw have been captured in honeypots since at least September 13, meaning active exploitation has been ongoing for 13+ days.
👤 Who's affected: Organizations running WSO2 API Control Plane, API Manager, Traffic Manager, or Universal Gateway — enterprise API infrastructure products widely deployed by corporations and government agencies to manage backend API access.
✅ What to do: Apply WSO2 patches immediately — the federal civilian deadline is September 27 (tomorrow); all organizations should treat this as an emergency patch given two weeks of confirmed in-the-wild exploitation and the gateway-level access this flaw provides.
🎯 ATT&CK: [Defense Evasion / Privilege Escalation] T1134.001 · Access Token Manipulation: Token Impersonation/Theft
Attackers craft forged JWT tokens using algorithms WSO2 incorrectly accepts, impersonating legitimate authorized users to bypass authentication entirely and gain unauthorized access to API management interfaces and all connected backends.
▶ Full analysis & beginner explanation
CVE-2026-5430 is a JWT algorithm confusion vulnerability. WSO2's authentication mechanism validates JSON Web Tokens used to authorize API requests, but it incorrectly accepts tokens signed with cryptographic algorithms that administrators never configured or sanctioned. An attacker exploits this by crafting a JWT signed with an unsupported algorithm (such as none or a weak symmetric key) that the WSO2 system validates as legitimate because it trusts the algorithm declared in the token's own header rather than enforcing what the admin configured.

Once a forged token passes validation, the attacker effectively impersonates any authorized user — including administrators — and can access all API endpoints, modify gateway configurations, and pivot to connected backend databases and microservices. WSO2 API products are frequently internet-exposed by design (they are API gateways), making this vulnerability directly reachable without any prior network access. The 13-day exploitation window means any WSO2 deployment with unusual JWT authentication attempts in logs since September 13 should be treated as potentially compromised.

The September 27 federal deadline is already causing emergency patch cycles in government environments. For the private sector, the urgency is equal — an API management platform compromise gives attackers a pivot point into every backend system the gateway protects.
🎓 For beginners: Think of a JWT as a digitally-signed concert pass. The signing is supposed to use a specific method both sides agreed on in advance. This bug lets attackers create a fake pass using a different signing method the system shouldn't trust — but mistakenly does. It's like a venue accepting a hand-drawn ticket when they were supposed to only accept printed holographic ones; the doorman is checking whether the ticket looks signed rather than whether it's signed correctly.

Roundcube Webmail CVE-2026-48842: Pre-Authentication SQL Injection Actively Exploited — Database Compromise Without Login
🔍 What happened: Canada's Cyber Centre updated advisory AV26-503 confirming active exploitation of CVE-2026-48842 (CVSS 8.1), a pre-authentication SQL injection flaw in Roundcube's virtuser_query plugin that lets unauthenticated attackers compromise the underlying database's confidentiality, integrity, and availability.
👤 Who's affected: Organizations and ISPs hosting Roundcube Webmail on versions before 1.6.16 or 1.7.1, including government mail servers and academic institutions that widely deploy this open-source webmail platform in Europe and internationally.
✅ What to do: Upgrade to Roundcube 1.6.19 or 1.7.4 (released September 6, 2026) immediately; if the virtuser_query plugin is not in active use, disable it as an additional mitigation until patching is complete.
🎯 ATT&CK: [Credential Access] T1212 · Exploitation for Credential Access
The pre-authentication SQL injection targets Roundcube's login flow database lookup, enabling attackers to extract user credentials and email account mappings from the database before any login challenge is presented.
▶ Full analysis & beginner explanation
CVE-2026-48842 exploits a subtle flaw in Roundcube's optional virtuser_query plugin. When a user enters their email address to log in, this plugin performs a database lookup to map the address to the correct mailbox account. A backslash escape bypass in the plugin's input processing allows attackers to inject arbitrary SQL into this pre-authentication query, gaining read and write access to the Roundcube database without ever presenting a valid password.

Successful exploitation gives attackers access to user credentials, email routing mappings, and potentially cached authentication tokens stored in the database. Roundcube is particularly popular in European government mail systems, academic institutions, and ISP-hosted email — making it historically attractive to espionage-focused actors. APT28 has previously been attributed to Roundcube exploitation campaigns targeting government email infrastructure in Ukraine and Eastern Europe, and while no specific attribution is confirmed for this current wave, the target profile matches established state-sponsored targeting patterns.

Roundcube addressed the original vulnerability in May 2026 (versions 1.6.16 and 1.7.1), then released updated security patches on September 6, 2026 (1.6.19 and 1.7.4). Any deployment still running pre-1.6.16 versions has been exposed for over four months.

Roundcube has a step where it looks up your email address in a database before asking for your password — this bug lets attackers slip extra database commands into that lookup step, potentially stealing everyone's credentials before the system ever checks if the attacker belongs there.

"MikroTrick" Chain (CVE-2026-67279 + CVE-2026-86060): Full Admin Takeover of MikroTik Routers With No Password Required
🔍 What happened: CISA added CVE-2026-67279 to its KEV catalog on September 25; when chained with CVE-2026-86060 in the "MikroTrick" exploit sequence, unauthenticated attackers gain full administrative control of MikroTik RouterOS by triggering an SSH session rekey during the authentication phase, causing the server to skip identity verification entirely.
👤 Who's affected: Organizations and ISPs running MikroTik RouterOS prior to versions 6.49.21, 7.23.4 (Long-term), or 7.24.2 (Stable) — MikroTik devices are widely deployed as edge routers, CPE equipment, and ISP infrastructure especially across Eastern Europe, Latin America, and SMB networks globally.
✅ What to do: Update RouterOS immediately to 6.49.21, 7.23.4, or 7.24.2; disable or restrict SSH access from untrusted networks; audit support files and router configuration for unauthorized changes that may indicate prior compromise.
🎯 ATT&CK: [Lateral Movement] T1021.004 · Remote Services: SSH
The MikroTrick chain exploits RouterOS's SSH state machine to skip the authentication phase entirely after a client-initiated key renegotiation, granting attackers unauthenticated command execution and the ability to alter network routing and intercept traffic.
▶ Full analysis & beginner explanation
The MikroTrick chain exploits a flaw in RouterOS's SSH state machine. Normal SSH authentication follows: key exchange → user authentication → session. CVE-2026-67279 abuses the rekey mechanism: when a client requests a key renegotiation (rekey) during the authentication phase, vulnerable RouterOS incorrectly advances to the session phase once the rekey completes — bypassing identity verification entirely. This gives an unauthenticated attacker an active SSH session with command execution capability.

CVE-2026-86060 escalates this to full administrative access, allowing attackers to create, overwrite, and reconstruct files in RouterOS's managed file namespace — including support files containing configuration and diagnostic data. In practice, attackers can modify routing tables, create persistent backdoor accounts, redirect traffic through attacker-controlled nodes for interception, and enlist the device in DDoS botnets. MikroTik routers have historically been compromised at scale to build botnets like Meris, which was responsible for some of the largest DDoS attacks on record.
🎓 For beginners: Imagine a bank vault requiring two steps: first show your ID, then use your key. This bug is a distraction trick — if you ask the vault to change its lock mid-process, it gets confused and lets you in without ever checking your ID. MikroTik routers handle internet traffic for many businesses and ISPs; a compromised router can silently redirect or copy all their customers' traffic to attackers.

💡 Today I Learned: JWT Algorithm Confusion Attacks ▶
A JSON Web Token (JWT) is a digitally signed credential passed between a client and server to prove identity — it contains claims like "this user is an admin" and a cryptographic signature that proves those claims haven't been tampered with. The signature is created using a specific algorithm (such as RS256 or HS256) that both the issuing server and the validating server agree on ahead of time. An algorithm confusion attack occurs when an attacker switches the algorithm declared in the token's own header to something weak or trivially-forgeable — like "none," which means no signature at all — and a poorly-implemented server trusts that self-declared algorithm rather than enforcing the one it was configured to expect, allowing the attacker to forge tokens and impersonate any user, including administrators, without knowing any secret keys.
📖 Glossary: JWT · SQLi · EoP · ALPC ▶
JWT — JSON Web Token; a compact, URL-safe standard for securely representing signed claims between parties, widely used for API authentication and session management.
SQLi — SQL Injection; an attack where malicious SQL statements are embedded in user-supplied input, manipulating the backend database query to exfiltrate or modify data.
EoP — Elevation of Privilege; a vulnerability class where an attacker gains higher system permissions than originally granted, often escalating from a regular user to administrator or SYSTEM level.
ALPC — Advanced Local Procedure Call; a Windows kernel mechanism for high-speed inter-process communication that has historically been a target for privilege escalation exploits.
