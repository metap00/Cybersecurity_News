Citrix NetScaler RCE Zero-Days CVE-2026-88771 & CVE-2026-88772 Actively Exploited Globally — Now Causing Post-Patch Reboots
🔍 What happened: Two critical RCE zero-days in Citrix NetScaler ADC and Gateway (CVSSv4 9.5 each) are being actively exploited worldwide to deliver web shells, and administrators who applied the emergency patches are now reporting unexpected appliance reboots triggered by crafted SAML authentication traffic.
👤 Who's affected: Any organisation running Citrix NetScaler ADC or NetScaler Gateway in a default configuration — this includes thousands of VPN and load-balancer deployments in healthcare, finance, and government sectors globally.
✅ What to do: Apply Citrix's emergency patches immediately, preserve forensic images before patching (updates may erase evidence), and hunt for web shells using CISA's published IOCs; if appliances are rebooting post-patch, check Citrix's updated advisory for the SAML workaround.
🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
Attackers sent unauthenticated HTTP requests to the NetScaler management interface — a public-facing application — to trigger the improper input validation flaw and execute arbitrary commands, bypassing all authentication controls.
▶ Full analysis & beginner explanation

CVE-2026-88771 is the more dangerous of the two: it requires no special configuration, no authentication, and no user interaction — affecting every NetScaler in its default state. The flaw stems from improper input validation in the management interface and allows arbitrary command execution. CVE-2026-88772 is a memory corruption bug requiring the DTLS feature to be enabled, making it harder to exploit reliably but still critical where DTLS is active.

Threat actors exploited both vulnerabilities as zero-days for weeks before Citrix's September 27 disclosure, delivering web shells that persist through reboots and grant persistent backdoor access. A new complication emerged October 2-3: a subset of patched appliances began rebooting in a loop when processing crafted SAML requests, suggesting either residual attacker activity or a patch interaction with SAML authentication middleware.

CISA added both CVEs to its Known Exploited Vulnerabilities catalog on September 27 and is urging federal agencies to patch immediately, while also advising forensic preservation before applying updates since patches may overwrite attacker artefacts.

The patch complication is like a locksmith's new lock occasionally jamming — the fix is real, but roll it out carefully.

Fortinet FortiMail CVE-2026-104286 (CVSS 9.8): Unauthenticated Arbitrary File Write Exploited in Wild — No Patch Available, Federal Deadline Oct 4
🔍 What happened: Fortinet disclosed CVE-2026-104286, a CVSS 9.8 path traversal + null-byte injection flaw in FortiMail that lets unauthenticated attackers write arbitrary files to the underlying Linux system via crafted HTTP/HTTPS requests — and no patch is yet available.
👤 Who's affected: Organisations running FortiMail 7.2.0–7.2.9, 7.4.0–7.4.8, 7.6.0–7.6.6, or 8.0.0–8.0.1 are vulnerable; attackers are using the flaw to plant backdoors on email gateway appliances.
✅ What to do: CISA mandates federal agencies remediate by October 4; until Fortinet releases patches, restrict management interface access to trusted IPs, audit file system integrity on exposed appliances, and review FortiMail logs for unexpected HTTP POST requests.
🎯 ATT&CK: [Persistence] T1505.003 · Server Software Component: Web Shell
The arbitrary file write capability in this FortiMail flaw is being leveraged to plant web shells on the email gateway's web root, giving attackers persistent remote access long after initial exploitation.
▶ Full analysis & beginner explanation

CVE-2026-104286 combines two classic weaknesses: path traversal (the attacker specifies a file path that escapes the intended directory, e.g., using "../../../") and null-byte injection (appending a null byte "\x00" to terminate a filename string before a forced extension is added). Together, they let an attacker write any file to any location on the system as the web server process user — including PHP web shells in the web root or malicious SSH authorized_keys entries.

Fortinet confirmed exploitation in the wild in advisory FG-IR-26-175 on October 1, but noted that corrected firmware versions are "upcoming" — meaning there are currently no fixed releases. Attackers have been observed backdooring FortiMail appliances with no password required, according to TechTimes, turning email security gateways into persistent footholds inside the network perimeter.

CISA's binding directive gives federal agencies until October 4 to remediate, a 72-hour window with no vendor patch available — highlighting how urgent this is. The only interim mitigations are network-level access controls to the management interface.

🎓 For beginners: FortiMail is a popular email security appliance that scans incoming email for spam and malware. This bug lets a hacker write any file to the device — imagine someone being able to slip a master key into your locks without knowing any password. Because there's no fix yet, the only defence is to make the device's management panel unreachable from the internet.

CVE-2026-20131 is a CWE-502 (Deserialization of Untrusted Data) flaw in the Cisco Secure Firewall Management Center's web interface. 💡 Today I Learned: Deserialization Attacks ▶
Serialization is how software converts a complex in-memory object (like a user session or a message) into a flat stream of bytes for storage or transmission — and deserialization is the reverse: reconstructing that object from the byte stream. Deserialization attacks exploit the fact that many programming languages (Java, PHP, Python) automatically execute code during this reconstruction, meaning if an attacker can inject a malicious serialized payload into any input that gets deserialized, they can run arbitrary code before any security check happens. The Cisco FMC zero-day (CVE-2026-20131) is a textbook example: Java deserializes the attacker's POST body without authentication, triggering a "gadget chain" — a sequence of already-loaded library methods that, when chained together in the right order, executes arbitrary shell commands as root.
📖 Glossary: RCE · KEV · FMC · Deserialization · RaaS · ELF ▶
RCE — Remote Code Execution; a class of vulnerability that allows an attacker to run arbitrary commands on a target system from across a network without physical access.
KEV — Known Exploited Vulnerabilities; CISA's continuously updated catalog of CVEs confirmed to be actively exploited in real-world attacks, which federal agencies are required to patch within binding deadlines.
FMC — Firewall Management Center; Cisco's centralised management console for administering Cisco Secure Firewall (formerly Firepower) appliances across an enterprise network.
Deserialization — The process of reconstructing a data object from a serialized (byte-stream) representation; when untrusted data is deserialized without validation, attackers can inject malicious payloads that execute code during reconstruction.
RaaS — Ransomware-as-a-Service; a criminal business model where ransomware developers license their malware and infrastructure to affiliates who conduct attacks in exchange for a percentage of ransom payments.
ELF — Executable and Linkable Format; the standard binary executable format for Linux and Unix-like operating systems, equivalent to Windows .exe files; attackers frequently drop ELF binaries containing malware tools onto compromised Linux servers.
