Lazarus Group Exploits Windows AFD.sys Zero-Day to Gain SYSTEM Access and Deploy Backdoor
🔍 What happened: North Korea's Lazarus Group exploited CVE-2026-68820, a use-after-free privilege escalation flaw in Windows' AFD.sys kernel driver, for five weeks before Microsoft patched it in August 2026 Patch Tuesday, using the zero-day to deploy a new "Troy" backdoor and the FudModule kernel-mode rootkit.
👤 Who's affected: Defense and aerospace professionals in France, Germany, Brazil, and India were targeted via fake job offers as part of Operation Dream Job; CISA has mandated federal agencies patch CVE-2026-68820 by August 25, 2026.
✅ What to do: Apply the August 2026 Patch Tuesday update immediately, prioritize CVE-2026-68820 on all Windows systems, and scrutinize unsolicited job outreach on professional networks for social engineering attempts.
🎯 ATT&CK: [Privilege Escalation] T1068 · Exploitation for Privilege Escalation
Lazarus triggered a race condition in the AFD.sys kernel driver to escalate from standard user privileges to SYSTEM, giving FudModule unrestricted kernel-mode access to hide its activity from security monitoring tools.
▶ Full analysis & beginner explanation

Check Point Research discovered that Lazarus Group — the prolific North Korean state-sponsored hacking collective — had been silently exploiting a zero-day vulnerability in AFD.sys, the Windows kernel driver underpinning the Winsock network API, since early July 2026. By triggering a use-after-free race condition in the driver, attackers could elevate their privileges from an ordinary user account to SYSTEM level, the highest possible on a Windows machine.

Once SYSTEM privileges were obtained, Lazarus deployed two novel tools: a previously undocumented backdoor named "Troy," which communicated through hijacked legitimate servers to blend into normal traffic, and a fresh version of FudModule, their sophisticated kernel-mode rootkit designed to blind endpoint detection and response (EDR) products by tampering with Windows security telemetry at the driver level. Targets were lured in through Operation Dream Job — elaborately crafted fake recruitment campaigns sent via LinkedIn and email, offering dream positions at defense contractors.

The attackers maintained access across defence and aerospace firms in France, Germany, Brazil, and India for approximately five weeks before the vulnerability was patched on August 12. CISA added CVE-2026-68820 to its Known Exploited Vulnerabilities (KEV) catalog and set an August 25 federal remediation deadline.

🎓 For beginners: Imagine your computer's core operating system as a locked building — normally no one can access the master control room. This bug is like a hidden flaw in the lock mechanism: by jiggling the handle in a very precise way (the "race condition"), Lazarus hackers could slip inside and become the building's all-powerful administrator, then install invisible cameras (the rootkit) that security guards couldn't see.
CVE-2026-68820 · CVSS: 7.8/10 — A high-severity local privilege escalation where an authenticated attacker with low-privilege access can gain SYSTEM rights, making it critical to patch even without remote exploitability.

China-Nexus APT Exploits VMware vCenter Zero-Day, Deploys Babuk Ransomware Across 47 Countries
🔍 What happened: A suspected China-linked threat actor began exploiting CVE-2026-59310, a CVSS 9.8 directory-traversal flaw in VMware vCenter, just five days after Broadcom released a patch on July 29, compromising 361 unique victim IPs across 47 countries and deploying Babuk-derived ransomware on ESXi hypervisors.
👤 Who's affected: Organizations running unpatched VMware vCenter Server in Germany, the US, Turkey, Iran, France, and 42 other countries were compromised; researchers believe ransomware deployment may have been a smokescreen concealing deeper espionage activity.
✅ What to do: Apply Broadcom's July 29 vCenter patch immediately, audit vCenter Server Appliance (VCSA) cron jobs for unauthorized entries, and treat any post-patch ESXi encryption as a possible multi-stage intrusion warranting full forensic review.
🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
The actor weaponized the directory-traversal vulnerability in internet-exposed vCenter Servers to achieve unauthenticated root-level code execution, bypassing all authentication controls to establish the persistent "linuxFile" backdoor via cron job.
▶ Full analysis & beginner explanation

CVE-2026-59310 is a critical directory-traversal flaw in VMware vCenter Server that allows an unauthenticated attacker to read and write arbitrary files on the server, ultimately achieving remote code execution at root level. Broadcom released a patch on July 29, 2026 — but within five days, a suspected Chinese-speaking threat actor (assessed with moderate confidence by German incident response firm QUIRSO based on UTC+08:00 operational timing) began mass-exploiting the vulnerability against internet-facing vCenter deployments.

The attackers established persistent access by implanting a backdoor named "linuxFile" via cron jobs on compromised vCenter Server Appliances (VCSA), then deployed a Babuk-derived ransomware locker to encrypt ESXi virtual machine files. Security researchers assess the ransomware deployment may have functioned as a smokescreen — encrypting ESXi log files to destroy forensic evidence and distract defenders from the deeper backdoor access. The campaign hit 361 unique victim IPs across 47 countries, with Germany (55), the US (41), Turkey (38), Iran (26), and France (25) among the hardest hit.

This incident reflects an accelerating trend: the average patch-to-exploitation window for enterprise virtualization platforms now measures in days, not weeks. Organizations that delay patching VMware infrastructure face near-certain exploitation by well-resourced state actors.

🎓 For beginners: VMware vCenter is like the master control panel for an entire data center's worth of virtual computers. This vulnerability was like a secret back door in that control panel that let attackers walk in without a key. Once inside, they set up a hidden alarm clock (the cron job backdoor) to let them back in later, then scrambled all the virtual machines' files like a burglar who also shredded the security camera footage on the way out.
CVE-2026-59310 · CVSS: 9.8/10 — Maximum-severity rating reflects unauthenticated remote code execution against a network perimeter management system, placing every virtual machine in a compromised vCenter's inventory at risk.

CoSnitch: Three Chained Copilot Flaws Enable Silent One-Click Data Theft from Connected Apps
🔍 What happened: Varonis Threat Labs discovered and responsibly disclosed three chained vulnerabilities in Microsoft Copilot Personal (collectively dubbed "CoSnitch," tracked as CVE-2026-24301) that allow a single malicious link click to trigger silent automatic data exfiltration from a victim's connected email, calendar, and cloud storage accounts to an attacker-controlled server; Microsoft shipped a fix on August 18, 2026.
👤 Who's affected: Users of Microsoft Copilot Personal with connected third-party app integrations are at risk if they interact with any attacker-crafted links before the August 18 patch; no evidence of in-the-wild exploitation was found prior to disclosure.
✅ What to do: Ensure Microsoft Copilot Personal is updated to the August 18 patch, review which third-party apps are connected to your Copilot account and revoke unnecessary permissions, and treat unsolicited Copilot-related links with the same caution as email phishing links.
🎯 ATT&CK: [Collection] T1213 · Data from Information Repositories
The CoSnitch exploit chain abused Copilot's own URL-fetching capability — designed for legitimate data lookup — to silently query connected email, calendar, and cloud storage repositories and tunnel the extracted content to an external attacker-controlled server, disguising the theft as routine AI traffic.
▶ Full analysis & beginner explanation

The "CoSnitch" vulnerability chain in Microsoft Copilot Personal combines three distinct weaknesses: (1) an undocumented URL parameter that triggers automatic prompt execution on page load, bypassing the need for any user input beyond clicking a link; (2) standard Copilot query logic that, once invoked, can silently pull data from all connected third-party apps (email, calendar, OneDrive, etc.); and (3) Copilot's built-in URL-fetching feature, which the attacker-crafted prompt weaponizes to exfiltrate the collected data to an external server disguised as routine Copilot API traffic.

What makes CoSnitch particularly notable is its discovery method — Varonis researcher Lior Adar employed what they term "meta-hacking": iteratively asking Copilot to explain why the attack was infeasible, then using Copilot's own increasingly detailed refutations to map its internal architecture. Copilot's transparent self-explanation ultimately revealed the exact undocumented parameter needed to make the attack work.

Microsoft patched all three underlying weaknesses on August 18, 2026 and confirmed no in-the-wild exploitation occurred prior to Varonis's responsible disclosure. However, the incident highlights structural risks inherent in AI assistants that combine broad data access with flexible natural-language execution — a pattern that will recur as AI integration deepens.

🎓 For beginners: Microsoft Copilot is an AI assistant connected to your email, files, and calendar. Imagine if someone could send you a magic link that, the moment you clicked it, made your AI assistant secretly email them copies of all your recent messages and documents — without showing you anything unusual happened. That's what CoSnitch did. The researcher found the bug by essentially tricking Copilot into explaining its own security flaws step by step, like a lock that describes how to pick itself.
CVE-2026-24301 · CVSS: not publicly disclosed — The vulnerability chain requires only a link click with no further user interaction to achieve full data exfiltration across all Copilot-connected services.

🎯 ATT&CK: [Exfiltration] T1530 · Data from Cloud Storage Object
The threat actor accessed a third-party cloud-based data storage platform holding Heights Finance customer records and exfiltrated the contents, demonstrating how compromising a vendor's cloud environment can expose customer PII at scale without ever touching the primary organization's own systems.
▶ Full analysis & beginner explanation

On May 7, 2026, Heights Finance Holdings — a consumer lending company — detected unauthorized access to a third-party cloud-based platform it used to store customer data. The attacker accessed a repository containing highly sensitive personally identifiable information (PII): full names, physical addresses, phone numbers, Social Security numbers, and financial account details for over 1.2 million borrowers. The company's own loan management systems and internal networks were not affected — the breach was entirely contained to the external vendor's cloud environment.

Heights Finance's dark web monitoring has not found evidence of the stolen data being sold or published as of the disclosure date. However, the combination of SSNs and financial details creates a rich dataset for identity theft, account takeover fraud, and targeted social engineering attacks. The company is offering 24 months of complimentary credit monitoring and identity protection services to all affected individuals.

No ransomware group or threat actor has claimed responsibility for the attack, and Heights Finance has not publicly identified the compromised third-party vendor. The incident reinforces a persistent security truth: organizations are only as secure as their vendors' weakest control.

🎓 For beginners: Heights Finance didn't get hacked directly — instead, a company they hired to store customer files got hacked. Think of it like a storage unit company that keeps copies of your personal documents getting broken into. The thieves got SSNs (Social Security numbers), which are like a master key to someone's financial identity — with those, criminals can open fraudulent credit cards, take out loans, or file fake tax returns in your name.
💡 Today I Learned: Kernel-Mode Rootkit ▶
A kernel-mode rootkit operates at Ring 0 — the innermost, most privileged layer of the operating system — where it can intercept and manipulate the raw data the OS reports to all other software. Because the kernel controls what security tools can "see," a rootkit at this level can hide malicious processes, files, and network connections from antivirus, EDR, and SIEM products that run at the unprivileged user level (Ring 3). Patching kernel vulnerabilities like CVE-2026-68820 is therefore especially urgent: once an attacker installs a kernel-mode rootkit like Lazarus Group's FudModule, the system can no longer be trusted to accurately report its own state — a complete reinstall may be the only way to ensure clean remediation.
📖 Glossary: Meta-hacking · Prompt Injection · Double Extortion · ESXi · CVSS · PoC ▶
Meta-hacking — Attacking an AI system by exploiting its own reasoning process and self-explanations rather than targeting underlying code; the CoSnitch researcher used Copilot's explanations of why an attack was impossible to discover the exact mechanism to make it possible.
Prompt Injection — An attack against AI/LLM systems where malicious instructions are embedded in data the model processes, causing it to override its original instructions and perform attacker-controlled actions instead.
Double Extortion — A ransomware tactic that combines file encryption with data theft, threatening to publicly publish the stolen data if the ransom isn't paid, giving attackers leverage even against victims with functional backups.
ESXi — VMware's bare-metal hypervisor (Type 1) that runs directly on server hardware without a host OS, allowing multiple virtual machines to share physical resources; its position as infrastructure backbone makes it a high-value ransomware target.
CVSS — Common Vulnerability Scoring System; a standardized 0–10 numerical framework (9.0–10.0 = Critical, 7.0–8.9 = High, 4.0–6.9 = Medium, 0.1–3.9 = Low) used industry-wide to communicate the severity of software vulnerabilities.
PoC — Proof of Concept; working exploit code that demonstrates a vulnerability is real and exploitable in practice; public PoC release dramatically accelerates the patch-to-exploitation window, as seen with CVE-2026-59310 being exploited within five days of the Broadcom patch.
