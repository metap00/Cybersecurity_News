CRITICAL Cybersecurity News / Splunk · Oct 7, 2026
Splunk Patches CVSS 9.8 Pre-Auth RCE: Exposed Patroni REST API Allows Unauthenticated OS Command Execution (CVE-2026-76268)
🔍 What happened: Splunk disclosed CVE-2026-76268, a CVSS 9.8 flaw in which the Patroni REST API on Splunk Enterprise search head cluster members is exposed without authentication, allowing any attacker with network access to execute arbitrary OS commands without needing credentials.
👤 Who's affected: Organizations running Splunk Enterprise 10.4.x before 10.4.3 or 10.2.x before 10.2.7 with search head clustering enabled; Splunk Cloud is not affected by this vulnerability.
✅ What to do: Update to Splunk Enterprise 10.4.3, 10.2.7, 10.0.10, or 9.4.15 immediately; if patching cannot happen today, restrict network access to the Patroni REST API and PostgreSQL sidecar endpoints as an interim mitigation.
🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
The unauthenticated Patroni REST API is exposed as a network service in many enterprise Splunk deployments, making CVE-2026-76268 a single-step path from network access to full OS command execution on the Splunk server — no credentials or user interaction required.
▶ Full analysis & beginner explanation

Splunk Enterprise's search head cluster architecture uses Patroni — an open-source PostgreSQL high-availability manager — to coordinate cluster membership and configuration changes. Advisory SVD-2026-1001 reveals that Splunk exposed the Patroni REST API without requiring authentication (CWE-306: Missing Authentication for a Critical Function). Because Patroni controls cluster-wide configuration operations, an attacker who reaches this interface doesn't just read data — they can reconfigure the cluster and inject commands that execute with the Splunk process's operating system privileges.

This is particularly dangerous because Splunk servers in enterprise environments often run with elevated privileges and sit on network segments alongside sensitive data sources: Active Directory audit logs, firewall telemetry, endpoint detection data. Compromising a Splunk instance means an attacker can both exfiltrate an organization's complete security history and alter or delete log data to erase their tracks — a dual-use threat that makes swift patching critical.

Splunk released fixed versions 10.4.3, 10.2.7, 10.0.10, and 9.4.15 on October 7. Versions 10.0.x and 9.4.x are not affected by this specific flaw but should still be updated for the broader advisory's fixes. No active exploitation has been confirmed yet, but given the ease of exploitation and the value of Splunk access to attackers, this should be treated as a P1 patching priority regardless.

🎓 For beginners: Splunk is like a massive security diary that records everything suspicious that happens on a company's network. This flaw means anyone on the same network as Splunk could walk up to its back door — a management interface called the Patroni API — and give it commands like "run this program" without ever needing a username or password. It's like discovering that the bank's vault has a maintenance hatch that anyone can open from the inside of the building.
CVE-2026-76268 · CVSS: 9.8/10 — Unauthenticated OS command execution via the Patroni REST API in Splunk Enterprise search head clusters; network-accessible with no credentials or user interaction required.

🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
Each vulnerable NX-OS feature exposes a network-accessible service that can be exploited without authentication; an attacker able to reach an affected Nexus switch over the network could gain root OS access to core data center switching infrastructure.
▶ Full analysis & beginner explanation

The October 2026 NX-OS hardening release addresses flaws across multiple feature sets. Key CVEs include: CVE-2026-76486 and CVE-2026-76501 (CVSS 9.8) in the NGOAM feature used for VXLAN OAM monitoring; CVE-2026-76471 (CVSS 9.8) in the NX-API heap-based buffer overflow; CVE-2026-76459 (CVSS 9.8) in improper access control; and CVE-2026-76455 (CVSS 9.8) — all involving improper input validation in network-facing interfaces. CVE-2026-76501 additionally requires both SRv6 and NGOAM to be simultaneously enabled, slightly reducing its exposure surface.

Cisco's advisory notes these were discovered through internal security testing and are not known to be exploited in the wild. However, data center switching infrastructure represents high-value targets — a compromised core switch provides network-wide visibility and interception capability. Organizations should validate their NX-OS feature inventory now, as many deployments enable monitoring features like NGOAM by default without reviewing whether those features introduce network-accessible attack surface.

🎓 For beginners: Cisco Nexus switches are the specialized computers that route network traffic inside large data centers — think of them as the highway interchanges of a company's internal internet. NX-OS is their operating system. These vulnerabilities are in add-on features of that OS: if those optional "lanes" are open, an attacker anywhere on the network could crash the whole interchange or secretly redirect all the traffic through their own server.

Budget Android Phones from Cubot and Doogee Found Shipping with Residential Proxy Malware Embedded in Firmware
🔍 What happened: Researchers discovered that low-cost Android smartphones from Cubot and Doogee ship from the factory with malicious code embedded directly in their firmware that secretly enrolls devices as residential proxy nodes, routing cybercriminals' traffic through victims' home internet connections.
👤 Who's affected: Buyers of affected Cubot and Doogee Android models who may unknowingly be providing their internet connection and device resources to criminal operations; the supply chain compromise predates the buyer receiving the device.
✅ What to do: Avoid purchasing Android phones from low-cost manufacturers with unclear supply chains; buyers of potentially affected devices should perform a full factory reset with a verified clean firmware image or replace the device; enterprise mobile device management policies should block non-approved devices.
🎯 ATT&CK: [Initial Access] T1195.002 · Compromise Hardware Supply Chain
Attackers embedded residential proxy malware directly in device firmware during manufacturing, compromising thousands of Android phones before they ever reached end users — making this a supply chain attack that bypasses all conventional endpoint security.
▶ Full analysis & beginner explanation

This campaign continues a documented pattern of firmware-level compromise targeting budget Android manufacturers. By embedding malware at the firmware level — not in a downloadable app — the malicious code persists through normal factory resets, is invisible to conventional antivirus apps, and cannot be removed without reflashing the device with a clean firmware image. Users first flagged anomalies on XDA Developers forums before researchers confirmed the malicious firmware components.

The proxy functionality allows cybercriminals to route attack traffic through victims' residential IP addresses, making their malicious requests appear to come from legitimate home users rather than data center or VPN exit nodes. This helps bypass IP-based blocking and fraud detection systems. Beyond proxying, such firmware implants are typically capable of credential theft, SMS interception, and installing additional malware at any time via command-and-control updates.

💡 Today I Learned: Missing Authentication for Critical Functions (CWE-306) ▶
CWE-306 describes the mistake of exposing a powerful internal function — like a cluster management API or an admin console — over the network without requiring any form of login or credential check, allowing anyone who can reach that network port to use it freely. Today's Splunk flaw (CVE-2026-76268) is a textbook example: the Patroni REST API, designed for internal cluster coordination, was network-accessible without authentication, turning an internal tool into a remote code execution entry point. Defenders can find and fix CWE-306 issues by reviewing every service that listens on a network port and asking whether it enforces authentication — if the answer is no, it should either require credentials or be firewalled to allow only specific internal systems.
📖 Glossary: CWE · Residential Proxy · NGOAM · Patroni · NX-OS ▶
CWE — Common Weakness Enumeration; a MITRE-maintained catalogue of named software and hardware weakness types (e.g., CWE-306: Missing Authentication) used to classify the root cause of vulnerabilities beyond just their CVE identifier.
Residential Proxy — a network of real consumer devices (home routers, phones) that have been infected with malware and rented out to route attackers' internet traffic, making malicious requests appear to originate from ordinary home IP addresses rather than data center servers.
NGOAM — Network Generic Operations, Administration, and Maintenance; a Cisco protocol for monitoring and troubleshooting VXLAN-based data center networks; when enabled on NX-OS devices it exposes a network-facing service that today's CVEs show can be exploited for unauthenticated root access.
Patroni — an open-source Python tool that manages high-availability clusters for PostgreSQL databases by coordinating leader election and configuration across cluster members; Splunk Enterprise uses it internally for search head cluster coordination, and its exposed REST API was the entry point for today's CVE-2026-76268.
NX-OS — Cisco's network operating system designed for Nexus data center switches and MDS storage switches; built for high-density, high-throughput environments, it supports advanced features like VXLAN, SRv6, and NGOAM whose optional activation can introduce significant attack surface.
