💡 Today I Learned: Return-Oriented Programming (ROP) ▶
Return-Oriented Programming (ROP) is an exploit technique where an attacker hijacks a program's execution by chaining together small snippets of existing code—called "gadgets"—each ending with a return instruction, without injecting any new code into memory. Because these gadgets are already part of legitimate programs loaded on the system, ROP can bypass classic defenses like Data Execution Prevention (DEP) that block running attacker-supplied code on the stack. Modern mitigations like Control-Flow Integrity (CFI) and hardware-enforced shadow stacks are designed specifically to detect and block ROP chains before they can execute malicious logic.
📖 Glossary: ROP · Gadget · Stack Canary ▶
ROP — Return-Oriented Programming; an exploitation technique that chains existing code "gadgets" ending in return instructions to execute arbitrary logic without injecting new code.
Gadget — A short sequence of CPU instructions ending in a "ret" (return) instruction that an attacker repurposes as a building block in a ROP chain.
Stack Canary — A random sentinel value placed on the program stack before the return address; if a buffer overflow overwrites it, the program detects the tampering and terminates safely.
