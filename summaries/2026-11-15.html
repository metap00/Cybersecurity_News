Telecom Data Breach Exposes 125 Million SMS Messages Across Baltic States
🔍 What happened: A publicly accessible, unauthenticated database at CSCTelecom's Latvian subsidiary exposed over 125 million SMS messages, including OTP codes and personal communications.
👤 Who's affected: Telecom subscribers in Latvia, Lithuania, and Estonia whose SMS messages—including one-time passwords for banking and authentication—were stored in the exposed system.
✅ What to do: Contact your carrier, monitor accounts for unauthorized access, switch from SMS-based 2FA to authenticator apps, and watch for targeted phishing using information gleaned from exposed messages.
🎯 ATT&CK: [Collection] T1530 · Data from Cloud Storage Object
Attackers accessed an improperly secured cloud-hosted database containing SMS logs with no credentials required, directly exfiltrating sensitive message content at scale.
▶ Full analysis & beginner explanation

The breach centers on a misconfigured cloud database operated by a subsidiary of CSCTelecom in Latvia that stored SMS message records without any access controls. With no authentication required, anyone who discovered the endpoint could read SMS traffic in bulk—including one-time passwords sent for banking logins, healthcare portals, and other sensitive services.

The severity here goes beyond the volume: SMS OTP codes are only valid for 30–120 seconds, but bulk access to live message streams could enable real-time account takeovers. Regulators in Latvia, Lithuania, and Estonia have been notified, and the database was taken offline after disclosure. Investigators have not yet attributed the exposure to a specific threat actor or confirmed how long the database was accessible.

🎓 For beginners: When you receive a text message with a login code, that message passes through your phone carrier's systems before it reaches you. If those systems store messages in a database that isn't locked down properly, anyone who finds it can read every code sent—including yours. This is why security experts recommend using an authenticator app (like Google Authenticator) instead of SMS codes whenever possible.
No CVE assigned · 125M+ records exposed — Scale qualifies as a critical-tier breach; real-time OTP exposure elevates risk beyond a standard database leak.

Exposed Fireworks AI Key Used to Backdoor Claude Code Extension and Breach Uber Driver Records

✅ What to do: Uninstall and reinstall all Claude Code IDE extensions from official sources, rotate any Fireworks AI API keys, audit CI/CD secrets and developer machine credentials, and check Uber's breach notification channels if you are a driver.
🎯 ATT&CK: [Initial Access] T1195.001 · Compromise Software Dependencies and Development Tools
Attackers leveraged a leaked service API key to inject malicious code into a trusted IDE extension update, turning the developer's own toolchain into the attack delivery mechanism.
▶ Full analysis & beginner explanation

The incident originates from an API key for Fireworks AI—an AI inference platform—being exposed, most likely through a leaked repository secret or misconfigured CI/CD environment. Attackers who obtained the key used it to authenticate as a legitimate publisher and push a malicious update to a Claude Code extension distributed through VS Code or Cursor's extension marketplace.

Once installed, the backdoored extension could harvest secrets, tokens, and credentials from the developer's local environment—exactly the kind of sensitive material that developers keep close at hand. Separately, the same compromised Fireworks AI credentials provided access to data Uber had stored on the platform, exposing U.S. driver records. The incident highlights a growing pattern: AI platform credentials are becoming high-value targets because they bridge AI tooling with broad data and code access.

🎓 For beginners: An API key is like a password that programs use to identify themselves to a service. In this case, an AI service's key leaked, letting attackers sneak malicious code into a developer tool that many programmers trust and run on their computers every day.

✅ What to do: Apply Check Point's November Jumbo Hotfix immediately — the CISA federal patch deadline is November 16 (tomorrow). Audit logs for exploitation attempts dating back to late October.
🎯 ATT&CK: [Privilege Escalation] T1068 · Exploitation for Privilege Escalation
Attackers first gained a web-tier foothold via PHP shell injection, then leveraged CVE-2026-123039 to escalate from application access to root on the Gaia OS firewall, achieving full appliance compromise.
▶ Full analysis & beginner explanation

CVE-2026-123039 affects Check Point's Gaia OS—the Linux-based operating system that runs on Check Point firewall and security gateway appliances. The vulnerability allows a low-privileged attacker who already has local access to escalate to root. In observed attacks, this was achieved through a two-step chain: attackers first used a web-facing PHP injection vulnerability ("PHP2Shell") to execute code in the web tier, then used CVE-2026-123039 to elevate that access to root, granting full control of the firewall.

CISA added this to the Known Exploited Vulnerabilities catalog on November 13 with an unusually short federal remediation deadline of November 16. The tight window reflects active exploitation observed since late October—attackers had a three-week head start before the public disclosure. Organizations should not wait for scheduled maintenance windows; this is a patch-now situation.

🎓 For beginners: A firewall is supposed to be your network's gatekeeper, blocking threats before they get in. When attackers can compromise the firewall itself, they don't just get through the gate—they become the gatekeeper, able to see everything and block nothing. This exploit chain let attackers use a weakness in a web page to get a foothold, then use a second bug to become the firewall's administrator.

SignDrop: Unpatched Windows CLFS Zero-Day with Working PoC Grants SYSTEM Privileges — No CVE, No Patch
🔍 What happened: Researcher MSNightmare published working exploit code dubbed "SignDrop" that abuses Windows' own CLFS log-signing protection to escalate any local user to SYSTEM on Windows 11 and Server 2025—with no CVE assigned and no patch from Microsoft as of today.
👤 Who's affected: Windows 11 and Windows Server 2025 systems; no in-the-wild exploitation confirmed yet, but the public PoC significantly lowers the barrier for attackers.
✅ What to do: Restrict local access to workstations, monitor CLFS driver activity in EDR logs, and watch for a Microsoft out-of-band security update. As a temporary measure, set HKLM\SYSTEM\CurrentControlSet\Services\CLFS\Authentication\Mode to audit mode.
🎯 ATT&CK: [Defense Evasion] T1562.001 · Disable or Modify Tools
SignDrop weaponizes Microsoft's own CLFS authentication hardening feature—a defensive control—turning it into a privilege escalation vector rather than bypassing it, exploiting the security mechanism's own signing logic.
▶ Full analysis & beginner explanation

What makes SignDrop unusual is what it doesn't do: it doesn't bypass a security feature. Instead, it exploits one. Microsoft shipped CLFS log file authentication as a hardening measure in October 2025 to prevent malicious manipulation of Windows log files—a technique used in several past Windows privilege escalation exploits (including previous CLFS zero-days). SignDrop, published 378 days after that hardening shipped, abuses the signing verification logic itself to reach SYSTEM.

As of November 15, Microsoft has not assigned a CVE, issued an advisory, or released a patch. The November 13 out-of-band update did not address SignDrop. With a working PoC now publicly available, threat actors capable of obtaining local execution—via phishing, initial access brokers, or other vulnerabilities—can chain SignDrop to become a SYSTEM-level attacker. Watch for a Microsoft emergency patch.

🎓 For beginners: Think of SYSTEM as the highest-level account on a Windows computer—more powerful than even an Administrator. A "privilege escalation" exploit is like finding a secret staircase from the ground floor to the penthouse. What's unusual here is that the attacker is using the building's own security camera system as the staircase—exploiting a safety feature rather than breaking through a wall.
No CVE assigned yet · CVSS: Pending — Unpatched zero-day with public PoC; risk escalates significantly with any in-the-wild adoption.

CVSS 9.8 Brotli Decoder Buffer Overflow (CVE-2026-111497) Hits Node.js and Siemens Industrial Systems
🔍 What happened: A critical buffer overflow in the Brotli compression decoder bundled with Node.js (CVE-2026-111497, CVSS 9.8) has been patched; the same library flaw also appears in Siemens Desigo CC building automation systems, now covered by CISA advisory ICSA-26-316-02.
👤 Who's affected: Organizations running Node.js web applications and operators of Siemens Desigo CC building automation and energy management systems.
✅ What to do: Update Node.js to the patched version immediately; Siemens Desigo CC operators should apply the ICSA-26-316-02 remediation steps and isolate affected systems from untrusted networks.
🎯 ATT&CK: [Lateral Movement] T1210 · Exploitation of Remote Services
A remote attacker supplying maliciously crafted Brotli-compressed data to a vulnerable Node.js or Siemens Desigo endpoint can trigger the buffer overflow to gain remote code execution without authentication.
▶ Full analysis & beginner explanation

Brotli is a data compression algorithm developed by Google that is widely used to speed up web traffic. Node.js bundles its own Brotli decoder, and a flaw in that decoder—CVE-2026-111497—allows an attacker to send specially crafted compressed data that overflows a memory buffer and potentially executes attacker-controlled code. With a CVSS score of 9.8, this is classified as critical, though no active exploitation in the wild has been confirmed.

The same underlying Brotli library also ships inside Siemens Desigo CC, a widely deployed building automation platform used for HVAC, lighting, and energy management in commercial and industrial facilities. CISA issued advisory ICSA-26-316-02 for this OT/ICS exposure. Industrial control system operators should treat the Siemens advisory as high priority: OT environments are often slower to patch, and a compromised building system can have physical consequences beyond data theft.

🎓 For beginners: Compression is used to send data faster over the internet—like squishing a file before mailing it. A "buffer overflow" bug means the program didn't check that the squished data would fit in the box before unpacking it, letting an attacker stuff in extra instructions that get run by accident. What makes this serious is that the same buggy compression code is used in both web servers and industrial building systems.
CVE-2026-111497 · CVSS: 9.8/10 — Critical buffer overflow in a widely-used compression library; no active exploitation confirmed but patch urgency is high given the score and OT/ICS scope.

💡 Today I Learned: API Key Security ▶
An API key is a secret token that identifies a program to a web service—the equivalent of a password for automated software, used in everything from AI platforms to cloud storage to payment processors. Unlike passwords, API keys are frequently embedded in code, CI/CD pipelines, and configuration files, where they're one careless git commit away from public exposure on GitHub. When an API key leaks, attackers gain the same access the legitimate program had—which in today's Fireworks AI incident meant the ability to publish malicious software updates and read stored customer data, all without breaking any encryption.
📖 Glossary: CLFS · NTLM · PoC · Infostealer · RMM ▶
CLFS — Common Log File System: a Windows kernel driver that provides a high-performance logging API; it has been exploited in multiple Windows privilege escalation zero-days over the past two years.
NTLM — NT LAN Manager: an older Windows authentication protocol that passes a hashed version of a password called an NTLMv2 hash; if intercepted, this hash can be "relayed" to other services to authenticate without knowing the actual password.
PoC — Proof of Concept: working code or a reproducible demonstration that confirms a vulnerability is exploitable; a public PoC dramatically lowers the skill bar for attackers, often triggering a surge in exploitation within days.
Infostealer — a category of malware designed to silently harvest credentials, browser cookies, saved passwords, cryptocurrency wallets, and other sensitive data from infected machines before exfiltrating them to an attacker's server.
RMM — Remote Monitoring and Management: software used by IT teams and managed service providers to remotely administer, monitor, and control endpoints; frequently targeted by attackers because legitimate RMM tools provide deep, trusted access to systems while often bypassing security controls.
