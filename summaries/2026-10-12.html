Qilin Ransomware Actively Exploiting Palo Alto GlobalProtect VPN Auth Bypass (CVE-2026-0257)
🔍 What happened: Qilin ransomware affiliates are exploiting an authentication bypass in Palo Alto GlobalProtect (CVE-2026-0257, CVSS 7.8) to forge VPN sessions without credentials and gain initial access to victim networks.
👤 Who's affected: Organisations using Palo Alto GlobalProtect or Prisma Access with override cookie authentication enabled and internet-exposed portals — estimated 167,000 instances online.
✅ What to do: Apply Palo Alto's May 2026 patch immediately; if already patched, disable override cookie authentication and restrict portal access to trusted IP ranges only.
🎯 ATT&CK: [Initial Access] T1133 · External Remote Services
Qilin affiliates exploit the GlobalProtect portal as an external remote service entry point, using forged override cookies to obtain authenticated VPN sessions that appear legitimate in network logs.
▶ Full analysis & beginner explanation

CVE-2026-0257 is a logic flaw in how GlobalProtect validates authentication override cookies — a feature intended for seamless single-sign-on. Palo Alto patched it in May 2026, but the CVSS score was initially reported as medium (4.7) and was only raised to 7.8 after CISA added it to the KEV catalog on May 29. This delayed prioritisation likely explains the large number of unpatched devices now being exploited.

Arctic Wolf Labs has investigated multiple intrusions in which every attack began at the firewall. After forging an authenticated VPN session, Qilin operators escalated privileges, performed lateral movement across the network, disabled backup and recovery tools, and then deployed ransomware. Some engagements involved double extortion, with data exfiltrated prior to encryption.

The attack requires an internet-exposed GlobalProtect portal or gateway with override cookie authentication enabled — a non-default setting that many enterprises turn on for seamless SSO. Organisations that patched but did not disable override cookies should review whether that feature is still necessary.

🎓 For beginners: Think of a VPN as a locked back door into your office network. A normal employee uses their key (password + certificate) to open it. This bug let Qilin attackers create a fake master key (a forged "override cookie") that the door lock accepted as valid — no password needed. Once inside the network, they moved from computer to computer until they owned everything, then scrambled all the files and demanded money.
CVE-2026-0257 · CVSS: 7.8/10 — High severity; network-accessible, no authentication required, directly enables ransomware deployment via VPN initial access.

🔍 What happened: A CVSS 9.8 zero-day in Fortinet FortiMail (CVE-2026-104286) that allows unauthenticated attackers to write arbitrary files to the underlying system was exploited in the wild and added to CISA's Known Exploited Vulnerabilities catalog on October 1, with a federal remediation deadline of October 4 that has now passed.
👤 Who's affected: Organisations running FortiMail versions 7.2.0–7.2.9, 7.4.0–7.4.8, 7.6.0–7.6.6, or 8.0.0–8.0.1 — especially those with the IBE (Identity-Based Encryption) feature enabled or with management interfaces internet-exposed.
✅ What to do: Upgrade immediately to fixed versions (8.0.2, 7.6.7, or 7.4.9); as a workaround, disable IBE via CLI and block external access to the management interface; review Fortinet advisory FG-IR-26-175 for published indicators of compromise.
🎯 ATT&CK: [Persistence] T1505.003 · Web Shell
Attackers leverage the arbitrary file write primitive to plant web shells on the FortiMail server, establishing persistent command-and-control access that survives reboots and credential rotations.
▶ Full analysis & beginner explanation

CVE-2026-104286 is an unauthenticated arbitrary file write flaw discovered internally by Fortinet's own Product Security team (Gwendal Guégniaud). Despite internal discovery, the flaw reached a CVSS 9.8 maximum score — reflecting that no authentication is required and that writing arbitrary files to a mail server gives an attacker near-total control: they can plant a web shell, overwrite configuration, or install persistent backdoors.

The IBE (Identity-Based Encryption) feature is implicated in the attack surface; disabling it removes the exploitable endpoint if patching is not immediately possible. Fortinet published IOCs in advisory FG-IR-26-175, including file hashes, network indicators, and log patterns that defenders can use to check for prior compromise.

CISA's October 4 federal deadline has passed for FCEB agencies, but any organisation running FortiMail should treat this as an emergency patch given the CVSS 9.8 score and confirmed in-the-wild exploitation. Organisations that cannot patch immediately should at minimum isolate the management interface from the internet.

🎓 For beginners: FortiMail is a piece of software that many companies use to filter spam and secure their corporate email. This bug lets a criminal send a specially crafted message to the FortiMail server without any login, and the server responds by saving a malicious file the attacker tells it to. That file can then be a "web shell" — essentially a secret remote control panel hidden on your email server — giving the attacker complete control over your mail infrastructure.
CVE-2026-104286 · CVSS: 9.8/10 — Critical; no authentication required, remotely exploitable, enables arbitrary file write leading to full server compromise.

GhostAction Campaign Compromises 346 GitHub Repositories via Hijacked Maintainer Accounts
🔍 What happened: A threat actor tracked as GhostAction hijacked two open-source maintainer accounts and injected a fake "security audit" GitHub Actions workflow into 346 repositories, exfiltrating secrets (API keys, tokens, credentials) from CI/CD pipelines.
👤 Who's affected: Open-source projects and their downstream users relying on the compromised repositories; any organisation whose CI/CD pipeline pulls from one of the 346 affected repos may have had secrets exposed.
✅ What to do: Audit GitHub Actions workflows for unexpected recent additions; rotate any secrets (API keys, tokens, passwords) that may have been accessible in affected CI environments; pin Actions to commit SHAs rather than mutable tags.
🎯 ATT&CK: [Credential Access] T1552.001 · Credentials in Files
The malicious workflow executed in the CI/CD environment and harvested credentials stored as GitHub Actions secrets, environment variables, and configuration files — a targeted credential theft via the build pipeline itself.
▶ Full analysis & beginner explanation

GhostAction is a supply chain attack campaign that used two legitimate but compromised maintainer accounts to appear trustworthy. By pushing a workflow disguised as a "security audit", the attacker exploited the implicit trust repositories place in contributions from known maintainers. GitHub Actions workflows run with access to repository secrets, giving the malicious workflow the ability to exfiltrate credentials to an attacker-controlled endpoint.

The attack is particularly dangerous because downstream users of the 346 affected repositories may not realise their CI pipelines pulled the malicious workflow version. Any build that ran while the malicious workflow was active may have exposed secrets — the scope of downstream impact is difficult to quantify without detailed audit logs from each affected project.

This attack reinforces the industry recommendation to pin GitHub Actions to immutable commit SHAs rather than mutable version tags (e.g., uses: actions/checkout@abc1234 instead of uses: actions/checkout@v4), and to use least-privilege token scopes in workflows.

🎓 For beginners: GitHub Actions is a system that automatically runs tasks (like testing code or deploying software) every time a developer makes a change. It works like a robot assistant that has the keys to many services. In this attack, criminals broke into the accounts of trusted developers, then added instructions telling the robot to secretly copy all the passwords it has access to and send them to the criminals. Because the instructions came from a known, trusted account, nobody noticed at first.

💡 Today I Learned: Authentication Override Cookies ▶
Authentication override cookies are a convenience feature in some VPN products that allow users to skip re-entering credentials by storing a cryptographically signed token in a browser cookie — once validated, the VPN gateway grants a full session without a password. When a bug like CVE-2026-0257 exists in the validation logic, attackers can forge or manipulate these cookies to trick the gateway into accepting them as legitimate, establishing an authenticated VPN session with no actual credentials. The lesson is that "convenience" features in security products often expand the attack surface: every alternative authentication pathway is a potential bypass, and features like override cookies should be disabled when not strictly necessary.
📖 Glossary: VPN · Supply Chain Attack · Double Extortion · Arbitrary File Write · ICS ▶
VPN — Virtual Private Network; an encrypted tunnel between a device and a corporate network that makes remote workers appear as if they are on the local office network.
Supply Chain Attack — An attack that targets software dependencies, build tools, or trusted third-party code to compromise the many downstream users who rely on that supply chain without directly attacking them.
Double Extortion — A ransomware tactic where attackers both encrypt victim files AND exfiltrate data beforehand, threatening to publish it publicly if the ransom is not paid — creating two independent levers of pressure.
Arbitrary File Write — A vulnerability class that allows an attacker to create or overwrite any file on a target system, often used to plant web shells, modify configuration, or replace system binaries.
ICS — Industrial Control System; computing equipment and software that monitors and controls physical processes such as power generation, water treatment, manufacturing assembly lines, and pipeline flow.
