PHP2Shell Exploitation Attempts Hit Millions as Mirai Botnet Joins Attacks
🔍 What happened: Two critical unauthenticated RCE vulnerabilities in the PHP engine (CVE-2026-109618 and CVE-2026-109619), dubbed PHP2Shell, are under massive active exploitation with Cloudflare observing millions of attempts within 24 hours of public disclosure, including Mirai botnet operators attempting to enlist vulnerable servers.
👤 Who's affected: Any server running PHP 8.2.x below 8.2.35, 8.3.x below 8.3.36, 8.4.x below 8.4.27, or 8.5.x below 8.5.12 — security firm Brandefense found 59% of scanned PHP servers still running a pre-fix version, covering an enormous portion of the internet's web infrastructure.
✅ What to do: Update PHP immediately to 8.2.35, 8.3.36, 8.4.27, or 8.5.12 — the vendor says patching is the only safe remediation, as available workarounds close only some attack paths.
🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
Attackers are directly exploiting the PHP engine's memory corruption (CVE-2026-109618) and stale global state (CVE-2026-109619) flaws to gain a pre-authentication foothold on internet-facing web servers without any credentials or user interaction.
▶ Full analysis & beginner explanation

PHP2Shell refers to two distinct but related vulnerabilities in the PHP scripting engine that together enable pre-authentication remote code execution. CVE-2026-109618 is an out-of-memory corruption flaw, while CVE-2026-109619 involves stale global state management. Together they can be chained to achieve arbitrary code execution without any login or user interaction on the target server.

Cloudflare reported tens of thousands of exploitation probes within 45 minutes of public disclosure, scaling to hundreds of thousands within 2 hours and millions by October 22. Sophos, which initially reported successful exploitation, has since clarified that its telemetry shows scanning and failed attempts but no confirmed compromises on its customer base. WatchTowr continues to report active exploitation attempts. The Dutch NCSC-NL also reported one unconfirmed possible case of exploitation abroad. The discrepancy reflects real uncertainty about whether mass-scale successful exploitation is occurring versus widespread probing.

Mirai botnet operators have joined the campaign, attempting to deploy a variant called Potassium onto vulnerable servers. Separately, VulnCheck published a sophisticated exploit for CVE-2026-109618 that includes an ASLR bypass using a memory leak to locate code in memory — this exploit is gated to paying subscribers but demonstrates that exploitation on hardened production systems is technically feasible.

🎓 For beginners: PHP is the programming language that quietly powers around 70% of all websites, including WordPress and many e-commerce platforms. These flaws let an attacker run their own commands on your web server without logging in — like finding a hidden door in a building that bypasses the security desk entirely. Millions of servers are potentially vulnerable, and attackers have been probing them since the bugs were announced. If your server runs PHP, update it now.
CVE-2026-109618 · CVSS: 9.2/10 — A memory corruption flaw in PHP's core engine that allows arbitrary code execution without authentication on any PHP-powered web server running a vulnerable version.

Critical FortiMail Zero-Day CVE-2026-104286 Exploited — Unauthenticated Attackers Writing Arbitrary Files and Deploying Malicious Libraries
🔍 What happened: A path traversal and NULL byte injection vulnerability in Fortinet FortiMail (CVE-2026-104286, CVSS 9.8) allows unauthenticated attackers to write arbitrary files to the underlying system; active exploitation has been confirmed with attackers deploying malicious shared libraries, modifying system binaries, and establishing data exfiltration channels to remote command-and-control servers.
👤 Who's affected: Organizations running FortiMail 7.2.0–7.2.9, 7.4.0–7.4.8, 7.6.0–7.6.6, or 8.0.0–8.0.1 as their email security gateway — enterprises across government, financial services, and healthcare that rely on Fortinet for email filtering are at highest risk.
✅ What to do: Apply Fortinet patches from advisory FG-IR-26-175 immediately; if IBE functionality is not required, disable it as a workaround; block C2 IPs 79.141.169.187 and 45.129.0.192, and investigate for a rogue "archive234" account indicating possible compromise.
🎯 ATT&CK: [Execution] T1574.006 · Hijack Execution Flow: Dynamic Linker Hijacking
After writing arbitrary files via the path traversal flaw, attackers injected malicious shared libraries into FortiMail's dynamic linker search path, causing their code to execute every time the mail gateway loads a legitimate process — a persistence technique that survives service restarts.
▶ Full analysis & beginner explanation

CVE-2026-104286 is a path traversal vulnerability combined with improper NULL byte neutralization in Fortinet FortiMail. Attackers craft a malicious HTTP/HTTPS request that includes a path traversal sequence (e.g., ../../) and a null byte terminator, tricking the server into writing a file to an arbitrary location outside the intended directory. At CVSS 9.8, this is about as severe as it gets for an unauthenticated pre-auth vulnerability.

CISA added the flaw to its Known Exploited Vulnerabilities catalog on October 1, 2026, the same day Fortinet published its advisory, and gave US federal civilian executive branch agencies only three days to remediate — a sign of how serious the active exploitation was. Forensic analysis from compromise investigations has found that attackers deploy malicious shared libraries and modify existing binaries to maintain persistent access even after patches are applied, meaning patching alone may be insufficient for already-compromised systems.

Indicators of compromise include an archive account named "archive234" configured to communicate with external IP 79.141.169.187, a second C2 at 45.129.0.192, and unexpected files in system directories or modifications to standard FortiMail binaries. Organizations should perform a full compromise assessment alongside patching.

🎓 For beginners: FortiMail is an email security appliance — a dedicated device or virtual machine that sits in front of your email server and scans incoming messages for spam, malware, and phishing. This vulnerability lets attackers plant their own programs inside it without needing a password, essentially turning your email security system into a backdoor into your network. Because these appliances are always on and internet-facing, they're extremely valuable targets.
CVE-2026-104286 · CVSS: 9.8/10 — Path traversal plus NULL byte injection enabling unauthenticated arbitrary file write on Fortinet FortiMail, granting attackers effective remote code execution and persistent access.

👤 Who's affected: Organizations running VeloCloud Orchestrator versions below 5.2.3.18, 6.1.3.10, or 6.4.2.12 for their SD-WAN deployment; CISA added CVE-2026-114625 to the KEV catalog on October 24 and cloud-hosted VCO instances have already been patched by Arista.

Attackers use any valid VeloCloud Orchestrator account — even a minimal read-only login — to trigger the SQL injection, abusing the legitimate account's authenticated session to escalate their own privileges to superuser without ever cracking an admin credential.
▶ Full analysis & beginner explanation

CVE-2026-114625 is a SQL injection vulnerability in Arista VeloCloud Orchestrator, the centralized management platform for Arista's SD-WAN product line. SQL injection in this context allows an attacker to send specially crafted input to a database query, causing the database to execute arbitrary commands rather than the intended query. In this case, the flaw allows an attacker with any valid login to manipulate database queries in a way that grants them operator-level superuser privileges.

This is the third exploited zero-day in VeloCloud Orchestrator in the span of four months, following CVE-2026-16812 (July) and CVE-2026-93952 (September). This pattern suggests sustained attacker interest in SD-WAN management infrastructure, possibly because VCO has operator visibility and control over a company's entire wide-area network — branch connectivity, traffic routing, and security policies. Compromising it could enable network-level manipulation and persistent access across the entire enterprise WAN.

Arista's advisory 0199 names two attacker IP addresses observed in exploitation, confirming real-world attacks. The CVSS 9.9 score reflects that even a low-privilege attacker can escalate to superuser with no workaround available. Organizations running VCO should check for logins from unfamiliar IP addresses, unusual privilege changes, or new user accounts in VCO audit logs.

▶ Full analysis & beginner explanation

The LiteLLM attack follows a pattern seen in previous supply chain compromises: rather than attacking the target organizations directly, attackers go after the developers who write the software those organizations trust. Attackers breached the GitHub organization approximately eleven days before the malicious release, suggesting a period of reconnaissance and access validation before the malicious payload was deployed. Windows Shell Zero-Day CVE-2026-96951 Exploited Before Patch — Mark-of-the-Web Bypass Removes Security Warnings on Downloaded Files
🔍 What happened: A Windows Shell security-feature bypass (CVE-2026-96951, CVSS 8.8), fixed in Microsoft's October 13 Patch Tuesday, was already being exploited in the wild before the patch shipped; it allows attackers to craft files that bypass Mark-of-the-Web (MotW) protections, stripping the Windows security warnings that normally appear when users open files downloaded from the internet or received via email.
👤 Who's affected: Any Windows user who receives and opens a maliciously crafted file via email, messaging, or a download link — Microsoft has not disclosed which organizations were targeted or what threat actor is behind the exploitation.
✅ What to do: Apply October 2026 Windows security updates immediately, and also apply CVE-2026-108398 which addresses a related WDAC enforcement bypass; train users to be cautious about opening unsolicited file attachments even if no security warning appears.
🎯 ATT&CK: [Defense Evasion] T1553.005 · Subvert Trust Controls: Mark-of-the-Web Bypass
Attackers exploited this zero-day to strip the Zone.Identifier alternate data stream from crafted files, causing Windows to treat attacker-delivered content as locally trusted rather than internet-origin — bypassing SmartScreen and Protected View warnings that are the last line of defense against phishing-delivered malware.
▶ Full analysis & beginner explanation

Mark-of-the-Web is Windows' mechanism for tracking the origin of files. When you download a file from the internet or open an email attachment, Windows tags it with a Zone.Identifier attribute indicating it came from an untrusted source. Programs like Microsoft Office, Windows Explorer, and Edge check this tag and trigger security warnings — Protected View in Office, SmartScreen in Windows — before executing potentially dangerous content.

CVE-2026-96951 allows an attacker to craft a file that causes Windows to not properly apply or check this tag, so the file opens without any security warning despite coming from the internet. This significantly lowers the barrier for phishing attacks: a malicious document or executable can reach users without triggering the warnings that might prompt a cautious person to stop. Microsoft confirms the flaw requires user interaction — a victim must be socially engineered into opening the malicious file — but the lack of any protective warning makes that social engineering much easier.

The flaw was discovered by researchers from Fujitsu and patched on Patch Tuesday October 13. Microsoft has not attributed the in-the-wild exploitation or disclosed affected industries. The CVSS 8.8 rating reflects the requirement for user interaction; without that requirement it would be rated higher. The related CVE-2026-108398 addresses a WDAC (Windows Defender Application Control) policy bypass that can be combined with MotW bypasses for deeper defense evasion.

🎓 For beginners: Imagine your email client is like a doorman at a building: when you get mail from a stranger, the doorman (Windows) stamps it "from outside" so the building's security systems know to check it carefully before letting it in. This vulnerability lets attackers remove that stamp — so a dangerous file walks right past security looking like it belongs there. The only defense once patching is done: be suspicious of any file you weren't expecting, even if Windows doesn't warn you.

🔍 What happened: Unit 42 (Palo Alto's threat research arm) confirmed that Qilin (Spikey Scorpius) and INC (Tarnished Scorpius) ransomware groups have been exploiting CVE-2026-0257, an authentication bypass in PAN-OS GlobalProtect VPN, to breach corporate networks across healthcare, education, financial services, government, and manufacturing sectors since at least May 2026.

💡 Today I Learned: ASLR Bypasses ▶
ASLR (Address Space Layout Randomization) is a memory security defense that randomizes where an operating system places key data — the stack, heap, and libraries — in memory every time a program runs, making it far harder for attackers to predict the exact memory addresses they need to exploit a vulnerability. When exploiting memory corruption bugs like PHP2Shell's CVE-2026-109618, attackers would normally be blocked by ASLR because they can't know where to point their exploit code; however, VulnCheck's PHP2Shell exploit demonstrates how ASLR can be defeated using a memory leak — a second, less severe bug that reveals the randomized address — essentially giving the attacker a "GPS coordinate" for what they need to overwrite. This two-stage technique (leak an address, then use it to aim a memory corruption exploit) is how modern exploit chains defeat ASLR, explaining why security engineers insist on patching even "minor" information disclosure vulnerabilities — they may be the first domino in a chain leading to full system compromise.
📖 Glossary: CVSS · PAN-OS · Webshell · Double Extortion · ASLR · VCO ▶
CVSS — Common Vulnerability Scoring System; a standardized 0–10 scale for rating software vulnerability severity, where 7.0–8.9 is High, 9.0–10.0 is Critical, and scores inform patching priority across the industry.
PAN-OS — Palo Alto Networks' proprietary operating system that runs on its hardware and virtual firewall and network security appliances, including GlobalProtect VPN gateways and next-generation firewalls.
Webshell — A malicious script (typically PHP, ASP, or JSP) uploaded to a compromised web server that gives an attacker a persistent, browser-accessible remote command interface, surviving reboots and often discovery by automated scanners.
Double Extortion — A ransomware tactic in which attackers both encrypt the victim's data and exfiltrate a copy, threatening to publish sensitive data publicly if the ransom is not paid, adding a data-breach liability dimension to the pressure.
ASLR — Address Space Layout Randomization; a memory protection technique that randomizes the location of the stack, heap, and libraries in memory at runtime, making it significantly harder for attackers to craft reliable exploits for memory corruption vulnerabilities.
VCO — VeloCloud Orchestrator; Arista's centralized management and orchestration platform for SD-WAN deployments, controlling traffic policies, QoS, and network configuration across all branch sites in an enterprise wide-area network.
