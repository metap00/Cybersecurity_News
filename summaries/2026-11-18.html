Microsoft Outlook CVE-2026-124194 NTLM Zero-Day Actively Exploited — CISA Demands Federal Patch by Nov 24
🔍 What happened: A zero-day spoofing flaw in Microsoft Outlook leaks NTLMv2 credential hashes to attacker-controlled servers when a victim merely previews a crafted email, requiring zero clicks.
👤 Who's affected: Any enterprise or organization running Microsoft Outlook on Windows where NTLM authentication remains enabled — the vast majority of corporate environments worldwide.
✅ What to do: Apply November 2026 Microsoft security updates immediately; CISA has added this to its Known Exploited Vulnerabilities catalog with a mandatory federal deadline of November 24, 2026.
🎯 ATT&CK: [Credential Access] T1187 · Forced Authentication
This flaw triggers an outbound NTLM authentication request from Outlook to an attacker's server simply by loading the malicious email, handing over NTLMv2 hashes for cracking or relay without any victim interaction.
▶ Full analysis & beginner explanation

CVE-2026-124194 is what researchers call a "zero-click" vector in its most dangerous form. A victim does not click a link or open an attachment — simply having the malicious email load in Outlook's reading pane triggers an outbound NTLM authentication request to an attacker-controlled server. The NTLMv2 hash that arrives can be cracked offline (especially effective against weaker passwords) or relayed immediately to authenticate to other internal services, achieving lateral movement across an enterprise network.

This class of NTLM leaking flaw has been exploited repeatedly over the years. Microsoft patched similar issues in CVE-2023-23397 and CVE-2024-21413. The persistence of these vulnerabilities reflects how difficult it is to remove NTLM from large enterprise environments — it is deeply embedded in legacy systems, printers, and network shares. Organizations that have completed the migration to Kerberos-only authentication are unaffected.

CISA's addition to the KEV catalog confirms active exploitation, meaning attacks are happening now. Threat actors using credential theft via this vector can quickly establish a foothold, pivot to Active Directory, and escalate privileges — often before defenders detect the initial email preview.

🎓 For beginners: Windows networks use a system called NTLM to prove who you are, like showing an ID badge. This bug tricks your Outlook email app into automatically showing that badge to a hacker's server the moment you view the email. The hacker captures a copy of your badge and can use it to walk into other servers in your company pretending to be you — without ever knowing your actual password.
CVE-2026-124194 · CVSS: 9.0/10 — High-severity spoofing flaw; network-reachable with no user interaction required beyond email preview in the reading pane.

Google Patches 8th Chrome Zero-Day of 2026: CVE-2026-125350 Use-After-Free Exploited in the Wild
🔍 What happened: Google released an emergency Chrome update fixing CVE-2026-125350, a use-after-free memory corruption flaw in the browser's XML parsing component that attackers are actively exploiting — the eighth Chrome zero-day patched in 2026.
👤 Who's affected: All Chrome users on Windows, macOS, Linux, and Android; also users of Chromium-based browsers including Microsoft Edge, Brave, and Opera which share the underlying rendering engine.
✅ What to do: Verify Chrome is on the latest version via chrome://settings/help (Chrome will auto-update but may need a restart to apply); Edge, Brave and other Chromium-based browsers should also be updated immediately.
🎯 ATT&CK: [Initial Access] T1189 · Drive-by Compromise
This use-after-free flaw in Chrome's XML parser is triggered when a user visits an attacker-controlled webpage, turning a normal browsing session into a code execution opportunity without any additional user interaction.
▶ Full analysis & beginner explanation

Use-after-free vulnerabilities in browser engines are among the most dangerous classes of memory corruption bugs. When Chrome frees a block of memory used for XML parsing and then attempts to use a pointer to that memory, an attacker who controls the XML input can arrange for attacker-controlled data to occupy that freed memory slot — potentially redirecting code execution to arbitrary instructions.

Eight Chrome zero-days in a single year reflects the enormous attack surface of modern browsers and the competitive market for browser exploits. High-sophistication threat actors — including nation-state groups and exploit brokers — pay premium prices for reliable Chrome RCE chains. The active exploitation of this flaw before Google patched it suggests it was part of an exploit chain, likely paired with a sandbox escape to achieve full OS code execution.

🎓 For beginners: Think of a use-after-free like erasing a whiteboard note and then accidentally reading from the erased spot — where an attacker has secretly written their own instructions. By crafting a malicious webpage that feeds Chrome a specially designed piece of XML data, the attacker can make your browser run their code just from you visiting the page.
CVE-2026-125350 · CVSS: 8.8/10 — High; renderer process exploitation potentially escaping the Chrome sandbox via a secondary privilege escalation step.

Barracuda Email Security Gateway CVE-2026-116606: Critical Authentication Bypass Grants Admin Access (CVSS 9.3)

Email security gateways sit at a privileged position in network architecture — all inbound and outbound email flows through them. An attacker with admin access can intercept communications, whitelist malicious senders to bypass spam filtering, disable antivirus and malware scanning, or silently copy all email to an external server. 💡 Today I Learned: NTLM Relay Attack ▶
An NTLM relay attack occurs when an attacker intercepts your Windows authentication request and immediately forwards it to another server as if they were you — the attacker never needs to know your password, only capture the authentication flow in transit. Because NTLM doesn't verify which server is being authenticated to, the attacker can use your credentials to log into internal file shares, databases, or even Active Directory domain controllers on your behalf. Modern defenses include disabling NTLM network authentication in favor of Kerberos, enabling SMB signing to prevent relay, and deploying Extended Protection for Authentication (EPA) — but millions of enterprise environments still have NTLM enabled because legacy devices require it.
📖 Glossary: NTLMv2 Hash · CVSS · UAF · Authentication Bypass · Extortion ▶
NTLMv2 Hash — The cryptographic token Windows sends when proving a user's identity over a network; if captured by an attacker it can be cracked offline or replayed to impersonate the user on other systems.
CVSS — Common Vulnerability Scoring System; a standardized 0.0–10.0 scale for rating vulnerability severity, where scores above 9.0 are considered Critical and demand immediate patching.
UAF (Use-After-Free) — A memory corruption bug where code uses a pointer to memory that has already been freed and potentially reallocated to attacker-controlled data, allowing arbitrary code execution.
Authentication Bypass — A vulnerability that allows an attacker to skip login procedures entirely and gain unauthorized access to a system or application without valid credentials.
Extortion — In a ransomware context, the practice of threatening to publicly release stolen data unless the victim pays a ransom, also called "double extortion" when combined with encrypting the victim's files.
