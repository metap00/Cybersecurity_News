Bitget Confirms North Korean Zero-Day Behind $387.5 Million Cryptocurrency Theft
🔍 What happened: North Korean hackers exploited a zero-day flaw in third-party security software integrated with Bitget to steal high-level internal credentials, then drained $387.5 million from hot and warm wallets across 11 blockchains in a ~3-hour window beginning September 24.
👤 Who's affected: Bitget customers whose funds were held in hot/warm wallets, plus $463 million in additional customer outflows following the disclosure.
✅ What to do: Cryptocurrency users should move significant holdings to cold (offline) storage; organizations should audit and isolate third-party security tool integrations from high-value credential stores.
🎯 ATT&CK: [Initial Access / Credential Access] T1078 · Valid Accounts
Attackers leveraged internal credentials stolen via the zero-day to authenticate as authorized users of Bitget's wallet management system, then issued fraudulent withdrawal commands that bypassed existing risk controls because the requests appeared to originate from legitimate high-privilege accounts.
▶ Full analysis & beginner explanation

Forensic analysis by blockchain security firm SlowMist revealed that attackers exploited a zero-day vulnerability in a third-party security product deeply integrated with Bitget's infrastructure — the specific vendor has not been publicly disclosed. By exploiting this flaw, the attackers obtained high-level internal credentials that granted them authority to issue withdrawal commands to the exchange's wallet management system.

The attack was remarkably precise and fast: the first abnormal transfer was logged at 02:31 UTC+8 and the last at 05:23, covering 11 blockchains including Ethereum, TRON, XRP Ledger, BNB Smart Chain, Avalanche, and several others. The fraudulent commands bypassed existing transaction-risk controls because they bore the signatures of legitimate administrative accounts, making real-time detection extremely difficult.

CEO Gracy Chen publicly attributed the attack to North Korea, citing IP address behavioral patterns and on-chain transaction analysis. North Korea-linked groups — principally Lazarus Group — have stolen billions of dollars in cryptocurrency since 2017, laundering proceeds to fund the DPRK's weapons programs. The Bitget incident may represent one of the largest single crypto heists attributed to the regime, exceeding the $625M Ronin Network hack of 2022 in operational speed if not total value.

Hackers found a hidden flaw in that company's software, used it to copy the fingerprints of the most powerful administrators, and then simply walked in and transferred $387.5 million out — all before anyone noticed, because the fingerprints looked genuine.

Fortinet FortiMail CVE-2026-104286 (CVSS 9.8): Null-Byte Path Traversal Actively Exploited — No Patch Available
🔍 What happened: Fortinet disclosed CVE-2026-104286 (CVSS 9.8), a null-byte path traversal vulnerability in FortiMail's HTTP/HTTPS management interface that allows unauthenticated remote attackers to write arbitrary files on affected devices; the flaw is actively exploited in zero-day attacks and patched versions are not yet available.
👤 Who's affected: Organizations running FortiMail 7.2.0–7.2.9, 7.4.0–7.4.8, 7.6.0–7.6.6, or 8.0.0–8.0.1 — virtually all supported FortiMail versions.
✅ What to do: Immediately disable IBE (Identity-Based Encryption) feature support on affected FortiMail appliances, or block all external access to the FortiMail management interface; apply Fortinet's upcoming patches (7.4.9, 7.6.7, 8.0.2) as soon as they release.
🎯 ATT&CK: [Persistence] T1505.002 · Server Software Component: Transport Agent
The arbitrary file write capability on FortiMail — a mail security appliance — allows attackers to implant persistent malicious components into the mail server's processing pipeline, analogous to how adversaries install malicious transport agents on mail servers to intercept, exfiltrate, or manipulate email in transit.
▶ Full analysis & beginner explanation

CVE-2026-104286 arises from improper null-byte handling in FortiMail's HTTP request parser. When the server processes file-path references in incoming requests, it fails to correctly sanitize null bytes (the \0 character), allowing an attacker to craft a path that appears to terminate at a safe location to the security check but is processed by the underlying OS as pointing to a sensitive directory. The result: any unauthenticated remote user can write arbitrary files anywhere on the appliance's filesystem.

The practical consequence is severe: attackers can overwrite configuration files, inject malicious code into server-side scripts, or install backdoors — all without a single valid credential. Because FortiMail handles organizational email security (spam filtering, antivirus scanning, encryption), a compromised appliance sits at the intersection of inbound and outbound corporate email, giving attackers a persistent position to intercept or manipulate communications.

Critically, Fortinet has confirmed active zero-day exploitation but has not yet shipped patches. The vulnerability was added to CISA's KEV catalog on October 1, 2026. The only available mitigations are disabling the IBE feature (which reduces attack surface exposure) or isolating the management interface from public internet access — effective but operationally disruptive for organizations relying on external management.

🎓 For beginners: FortiMail is a security appliance that screens all incoming and outgoing company email. This vulnerability is like discovering that the building's security guard — the one who checks every letter for threats — has an unlocked back door that anyone can walk through to reach the filing room. Attackers can slip through that back door and rewrite the rulebook the guard uses, potentially letting them read every email or make the guard wave through malicious messages.

🔍 What happened: Apple released emergency patches for CVE-2026-86950 (CVSS 8.8), an out-of-bounds write in the CoreGraphics font glyph rasterizer triggered by maliciously crafted PDF files (likely delivered via WhatsApp), enabling arbitrary code execution in "extremely sophisticated" targeted attacks discovered by Meta Product Security.
👤 Who's affected: iOS, iPadOS, and macOS users on unpatched versions; attack pattern suggests high-value targets including journalists, executives, and activists.
✅ What to do: Update immediately to iOS/iPadOS 26.7.1, macOS Tahoe 26.7.1, or macOS Sequoia 15.8.1; CISA's October 2 deadline for federal agencies applies today.
🎯 ATT&CK: [Execution] T1204.002 · User Execution: Malicious File
Attackers delivered malicious PDF files (likely via WhatsApp) that, when the device's CoreGraphics framework processes the embedded font glyphs, triggers an integer overflow leading to an out-of-bounds write — the payload executes when the user opens or previews the file, making them an unwitting participant in their own device compromise.
▶ Full analysis & beginner explanation

CVE-2026-86950 sits in CoreGraphics, Apple's foundational graphics rendering framework used across iOS, iPadOS, and macOS. Security firm Calif traced the root cause to an integer overflow in the font glyph rasterizer — when the system renders certain maliciously crafted font characters embedded in a PDF, it performs a size calculation that overflows, causing the system to write attacker-controlled data past the end of an allocated memory buffer. This out-of-bounds write can be shaped into arbitrary code execution.

The attack vector is particularly insidious: PDF processing is deeply integrated into iOS, meaning a WhatsApp message preview or Files app thumbnail could trigger exploitation without the user explicitly opening a document. Meta Product Security, credited with the discovery, assessed the attack as "extremely sophisticated," language Apple reserves for state-grade capability. The pattern — targeted delivery via messaging apps, PDF lure, CoreGraphics exploit — echoes documented NSO Group and Intellexa campaign methodologies.

🎓 For beginners: Every iPhone uses CoreGraphics to draw text and images on screen, including rendering fonts inside PDFs. This bug means a cleverly crafted font in a PDF can overflow like a glass of water poured too fast — and the overflow splashes into the wrong memory area, overwriting instructions with attacker code. The attacker just needs to send you a PDF in WhatsApp; you might not even need to open it fully.

Microsoft Defender 'ShieldCrash' Zero-Day PoC Released: SYSTEM-Level File Read Bypasses September Patch on All Supported Windows
🔍 What happened: Researcher "Nightmare Eclipse" published a proof-of-concept (PoC) exploit called ShieldCrash that reads arbitrary files — including the SAM database and registry hives — with SYSTEM-level privileges on fully patched Windows, representing an incomplete fix for CVE-2026-69414 (ShieldBreak) from September 2026 updates.
👤 Who's affected: All supported Windows versions (including fully patched post-September 2026 systems) in enterprise environments where credential theft via SYSTEM access could enable lateral movement.
✅ What to do: Monitor for anomalous reads of SAM, NTDS.dit, and registry hive files using EDR tools; enforce least-privilege and application controls; await Microsoft's emergency patch addressing the incomplete CVE-2026-69414 fix.
🎯 ATT&CK: [Defense Evasion] T1562.001 · Impair Defenses: Disable or Modify Tools
ShieldCrash exploits a flaw within Microsoft Defender itself to achieve SYSTEM-level file access, effectively turning the security tool against the system it protects — an attacker who abuses this can read credential stores while Defender remains blind to the activity, directly impairing the defensive capability the tool is meant to provide.
▶ Full analysis & beginner explanation

ShieldCrash is a bypass of Microsoft's September 2026 patch for CVE-2026-69414 (ShieldBreak), which previously allowed SYSTEM privilege escalation via Defender. The researcher "Nightmare Eclipse" demonstrated that the underlying access control misconfiguration was only partially corrected: the PoC can still read arbitrary files — including the SAM (Security Account Manager) database, NTDS.dit (Active Directory password hashes), and critical registry hives — with SYSTEM-level permissions.

The SAM and NTDS.dit databases contain hashed credentials for every local and domain user account respectively. Reading them with SYSTEM access enables offline hash cracking or pass-the-hash attacks, providing a direct path to lateral movement and domain compromise. The attack requires local code execution (not a remote exploit), meaning it would typically be used as a privilege escalation step after an initial foothold is established.

Microsoft has been notified and is reportedly working on a supplemental patch. Until then, organizations should prioritize monitoring for Defender-related file access anomalies, particularly any process reading from \%SystemRoot%\System32\config\SAM or NTDS.dit outside expected backup windows.

🎓 For beginners: SAM is a database Windows keeps locked in a vault — it stores all the password hashes for every user account. ShieldCrash tricks Windows Defender (your security guard) into using its own master key to open that vault and hand over the contents. Microsoft tried to fix a similar issue last month but left a gap, and a researcher just showed that gap is still exploitable on every up-to-date Windows machine.

💡 Today I Learned: Null Byte Injection ▶
A null byte is the character with ASCII value zero (\0) — it signals "end of string" in the C programming language, but web applications written in higher-level languages often process it as a literal character. When an attacker inserts a null byte into a filename or file path sent to a vulnerable server (e.g., ../../etc/passwd%00.jpg), the web application sees a harmless ".jpg" path and allows it through, while the underlying operating system or C library truncates at the null byte and reads the actual sensitive file. The FortiMail CVE-2026-104286 exploits exactly this mismatch: the HTTP interface fails to strip null bytes before passing paths to the OS, allowing attackers to write arbitrary files anywhere on the appliance by crafting requests that bypass the path-safety checks.
📖 Glossary: IBE · Path Traversal · SAM · Out-of-Bounds Write · PoC ▶
IBE — Identity-Based Encryption; a cryptographic scheme in email security (used by FortiMail) where a recipient's email address itself serves as their public key, eliminating the need to exchange certificates in advance.
Path Traversal — An attack where an attacker manipulates file path variables (e.g., using ../ sequences) to access files and directories outside the intended directory, potentially reaching sensitive system files.
SAM — Security Account Manager; the Windows database that stores hashed passwords for local user accounts, located at %SystemRoot%\System32\config\SAM and normally inaccessible even to administrators while the OS is running.
Out-of-Bounds Write — A memory corruption vulnerability where a program writes data past the end of an allocated buffer; attackers can craft the overflow to overwrite adjacent memory with malicious code, often leading to arbitrary code execution.
PoC — Proof of Concept; a working piece of exploit code released (typically by researchers) to demonstrate that a vulnerability is real and practically exploitable, used to pressure vendors into patching but also a risk if weaponized by attackers.
