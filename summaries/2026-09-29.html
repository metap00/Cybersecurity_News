Two critical zero-day vulnerabilities in Citrix NetScaler ADC and Gateway have been actively exploited in the wild since early September 2026—almost a month before Citrix issued patches on September 27. CVE-2026-88771 stems from improper input validation and permits unauthenticated attackers to execute arbitrary OS commands on any default-configured NetScaler appliance; Citrix assessed the attack complexity as "low," meaning reliable exploitation requires no special knowledge. 🎓 For beginners: Citrix NetScaler is a popular networking appliance that sits between the internet and an organization's servers, handling web traffic for thousands of enterprises worldwide. 'ShieldCrash' Zero-Day Bypasses September Defender Patch, Claims SYSTEM-Level Access on All Supported Windows Versions
🔍 What happened: A researcher known as Nightmare Eclipse released a proof-of-concept exploit called ShieldCrash immediately after Microsoft's September 2026 Patch Tuesday, claiming it grants SYSTEM-level privileges on fully patched Windows 10, Windows 11, and Windows Server by abusing a flaw in Microsoft Defender's Malware Protection Engine—bypassing the ShieldBreak patch shipped in August.
👤 Who's affected: All Windows users with Microsoft Defender enabled (virtually all Windows 10, 11, and Server installations by default); Microsoft has not yet assigned a CVE or CVSS score as of publication.
✅ What to do: Keep Defender and Windows Update set to automatic; monitor the Microsoft Security Response Center (MSRC) for an out-of-band patch; independent analysis suggests the public PoC may be incomplete, but the underlying flaw appears real.
🎯 ATT&CK: [Privilege Escalation] T1068 · Exploitation for Privilege Escalation
ShieldCrash abuses a flaw in Defender's Malware Protection Engine to escalate from standard user to SYSTEM, the highest Windows privilege tier, bypassing the previous ShieldBreak patch and enabling full system control.
▶ Full analysis & beginner explanation

ShieldCrash is the third consecutive Microsoft Defender privilege escalation exploit in 2026, representing a systematic campaign of bypass-after-bypass against the same core component. The chain began with RoguePlanet (patched July 2026), was followed by ShieldBreak (dropped on the August Patch Tuesday), and now ShieldCrash (dropped on the September Patch Tuesday). Each exploit bypassed the previous fix, indicating that researchers—or threat actors—have deep visibility into Defender's Malware Protection Engine internals.

Nightmare Eclipse claims the exploit enables arbitrary file reads as the SYSTEM account, which would allow an attacker who already has normal user access to read any file on the system—including credential stores, security configurations, and sensitive documents—without triggering standard permission checks. Microsoft has not yet assigned a CVE identifier or CVSS score. Importantly, independent analysis by Howler Cell assessed with high confidence that the public PoC code, as released, does not successfully perform the claimed arbitrary file read—suggesting the PoC may be intentionally neutered or the claim overstated. However, the underlying vulnerability pattern appears legitimate.

The pattern of rapid patch bypasses suggests organizations should not rely on Defender alone for privilege escalation prevention and should layer additional controls such as application whitelisting, EDR solutions, and least-privilege enforcement.

🎓 For beginners: SYSTEM is the highest privilege account on a Windows computer—even above Administrator. If an attacker already has a foothold on your machine (perhaps from clicking a phishing link) but only has limited user access, they can use a privilege escalation exploit like ShieldCrash to "level up" to full SYSTEM control, letting them do anything: install ransomware, disable antivirus, or steal all passwords. The fact that this is the third bypass in a row suggests Microsoft's patches keep addressing symptoms rather than the root cause in Defender's engine.

ShinyHunters Weaponizes URL-Encoding WAF Bypass to Resume Oracle PeopleSoft CVE-2026-35273 Exploitation
🔍 What happened: ShinyHunters, which already breached 100+ organizations via the critical Oracle PeopleSoft zero-day CVE-2026-35273 (CVSS 9.8) earlier this year, discovered that organizations relying on WAF rules as the sole mitigation are still vulnerable—the group is now using URL percent-encoding to obfuscate the exploit payload and bypass those WAF defenses.
👤 Who's affected: Universities, government agencies, and enterprises running Oracle PeopleSoft versions 8.61 or 8.62 that applied WAF-rule mitigations but have not installed Oracle's June 2026 patch are now once again fully exposed to unauthenticated RCE.
✅ What to do: Apply Oracle's June 2026 security patch for CVE-2026-35273 immediately—WAF mitigations alone are insufficient; audit PeopleSoft logs for anomalous HTTP requests with percent-encoded characters; assume compromise if patched after late May 2026.
🎯 ATT&CK: [Defense Evasion] T1027 · Obfuscated Files or Information
ShinyHunters uses URL percent-encoding to disguise the CVE-2026-35273 exploit payload, causing WAF rules that block the raw attack string to pass the obfuscated version through undetected and deliver the exploit to the vulnerable PeopleSoft endpoint.
▶ Full analysis & beginner explanation

CVE-2026-35273 is an unauthenticated RCE vulnerability in Oracle PeopleSoft Enterprise PeopleTools 8.61 and 8.62 (Updates Environment Management component) with a CVSS score of 9.8. Between May 27 and June 9, 2026—before Oracle patched it on June 10—ShinyHunters exploited it to compromise approximately 300 PeopleSoft instances and steal data from over 100 organizations, predominantly in the higher education sector. Oracle patched the vulnerability and many organizations deployed WAF rules as a faster-to-implement interim mitigation.

ShinyHunters has now discovered that WAF rules blocking the specific attack string can be trivially defeated by URL-encoding (percent-encoding) some or all of the exploit payload characters. Web applications decode percent-encoded characters before processing, so the actual PeopleSoft endpoint receives and executes the original exploit—while the WAF sees an obfuscated string that doesn't match its detection signature and passes it through. This is a classic WAF bypass technique that underscores why patch-based fixes are always superior to signature-based WAF mitigations for critical vulnerabilities.

Google Threat Intelligence has warned that unpatched PeopleSoft instances remain high-value targets for ShinyHunters, whose campaign motivation is data theft for extortion—stealing student records, financial data, and research from universities.

🎓 For beginners: A WAF (Web Application Firewall) works like a security guard reading every request for known "bad words" before letting it through. URL encoding is like writing those bad words in a code—replacing letters with their numeric equivalents (e.g., %41 for "A")—so the guard doesn't recognize them. The server on the other side still understands the coded message perfectly. This is why patching the actual software vulnerability is always the right answer: it fixes the underlying flaw regardless of how the attack is disguised.

💡 Today I Learned: Webshell Persistence ▶
A webshell is a malicious script—often a few lines of PHP, ASP, or JSP—uploaded to a compromised web server that gives attackers a persistent, browser-accessible command interface; as long as the file exists on disk, the attacker can reconnect at any time by sending an HTTP request to that URL, regardless of whether the original exploit vulnerability was patched. Webshells are particularly dangerous because they blend in with legitimate web application files, operate over the same port (443) as normal HTTPS traffic making them hard to block at the firewall, and can be encoded or obfuscated to evade antivirus signature scans. Defenders combat webshells through file integrity monitoring (alerting on any new or modified files in web-accessible directories), anomaly detection for unusual HTTP request patterns (e.g., a request to a file name ending in ".php" in an image directory), and regular threat-hunting exercises that actively look for webshell artifacts rather than waiting for alerts.
📖 Glossary: APT · CVSS · Hot Wallet · Webshell · Zero-Day ▶
APT — Advanced Persistent Threat; a sophisticated, often nation-state-backed hacking group that conducts long-term, stealthy intrusion campaigns against high-value targets using custom tooling and careful operational security.
CVSS — Common Vulnerability Scoring System; a standardized framework that assigns a numerical severity score (0.0–10.0) to security vulnerabilities based on factors including exploitability, required privileges, attack complexity, and potential impact.
Hot Wallet — A cryptocurrency wallet that remains connected to the internet to enable fast transaction processing, making it convenient for exchanges but significantly more vulnerable to theft than an offline cold wallet.
Webshell — A malicious script (typically PHP, ASP, or JSP) uploaded to a compromised web server that gives attackers persistent remote command execution through standard HTTP requests, often surviving patching if not actively hunted and removed.
Zero-Day — A software vulnerability that is unknown to the vendor or has no available patch at the time of discovery, giving defenders "zero days" to remediate before attackers exploit it; particularly dangerous when found and weaponized before the vendor is aware.
