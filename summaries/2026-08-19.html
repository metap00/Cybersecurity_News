Hacker "TheHatman" Claims Millions of Records Stolen from Azure Tenants at McDonald's, Vodafone, and Fortune 500 Companies
🔍 What happened: A threat actor using the handle "TheHatman" posted millions of employee records allegedly exfiltrated from Azure corporate tenants — including 1.7 million from McDonald's, 800,000 from TCS, and 425,000 from Vodafone — on cybercrime forums, claiming access via password spraying and MFA fatigue.
👤 Who's affected: Employees at McDonald's, Vodafone, TCS, Kyndryl, HCL, and other Fortune 500 companies whose Azure environments were targeted are at risk of phishing and identity theft.
✅ What to do: Organizations should audit Azure sign-in logs for anomalous authentication activity, enforce phishing-resistant MFA (FIDO2 hardware keys rather than push-notification approval), and apply conditional access policies to block password spraying patterns.
🎯 ATT&CK: [Credential Access] T1110.003 · Brute Force: Password Spraying
TheHatman systematically tested commonly-used and previously-leaked passwords across Azure corporate tenants to compromise accounts, then used MFA push-bombing to bypass authentication — a textbook password-spraying campaign enhanced with social engineering to defeat MFA controls.
▶ Full analysis & beginner explanation

TheHatman, an unidentified threat actor who surfaced in August 2026, has been systematically posting large employee record sets allegedly exfiltrated from the Azure Entra ID directories of major corporations. The dumped data includes employee names, IDs, job titles, and contact information — the kind of structured directory export consistent with full Active Directory access rather than scraping from a public API. McDonald's tops the alleged victim list at 1.7 million records, followed by TCS at roughly 800,000 and Vodafone at approximately 425,000.

The claimed attack method combines two proven techniques: password spraying (testing a small set of commonly-used or previously-breached passwords against a large number of accounts to avoid lockout thresholds) and MFA fatigue, also called push bombing. In MFA fatigue, the attacker continuously sends authentication push requests to enrolled devices until an overwhelmed or inattentive user taps "Approve." Together, these techniques bypass even organizations that have deployed MFA — the spray defeats the password requirement, and the fatigue defeats the second factor.

TCS filed a statement with the Bombay Stock Exchange on August 10 after receiving threat intelligence alerts, saying it had found "no credible evidence" of a breach of its own systems and suggesting the data appeared more than four years old. This raises the possibility that some claimed victims had data stolen from a third-party HR or identity management platform with Azure integrations, rather than directly from their own tenants. Investigations are ongoing across multiple companies.

🎓 For beginners: Your company's employee directory — everyone's name, work email, and job title — lives in a cloud system called Azure Active Directory. Hackers can automatically try thousands of common passwords against this system (password spraying) without triggering lockouts. When the system then sends a "Did you just sign in?" notification to employees' phones, the attacker spams that notification repeatedly until someone, exhausted or distracted, accidentally taps "Yes." The hacker then downloads the entire employee list and sells it on criminal forums.
No CVE assigned — attack leverages credential abuse techniques against legitimate authentication infrastructure rather than exploiting a software vulnerability.

Attackers Exploit MLflow SSRF Flaw (CVE-2026-64849, CVSS 9.3) to Steal Cloud Credentials and Secrets Within Hours of Disclosure
🔍 What happened: Active exploitation of CVE-2026-64849, an unauthenticated SSRF vulnerability in MLflow's webhook test endpoint (CVSS 9.3), began within hours of its August 17 disclosure, with attackers redirecting server requests to internal cloud metadata APIs to harvest IAM tokens and deployment secrets.
👤 Who's affected: Organizations running internet-exposed MLflow instances below version 3.15.0 — particularly ML/AI teams on AWS, Azure, or GCP — face cloud credential theft that could give attackers broad access to their entire cloud environment.
✅ What to do: Upgrade MLflow to version 3.15.0 immediately, restrict network access to MLflow deployments so they are not internet-exposed, and rotate any cloud IAM credentials that may have been accessible from compromised instances.
🎯 ATT&CK: [Credential Access] T1552.005 · Unsecured Credentials: Cloud Instance Metadata API
Attackers redirect MLflow webhook test requests to the cloud instance metadata service (169.254.169.254) via HTTP redirect, bypassing URL validation to extract IAM credentials and secrets from the cloud environment's metadata endpoint — a classic SSRF path to cloud credential theft.
▶ Full analysis & beginner explanation

MLflow is an open-source platform used by data science teams to track ML experiments, manage model versions, and orchestrate pipelines. CVE-2026-64849 is an unauthenticated SSRF flaw in the webhook test endpoint (/api/2.0/mlflow/webhooks/{id}/test). When MLflow tests a webhook, it makes an HTTP request to the registered URL — and critically, follows any HTTP redirects returned by that URL without restriction on the redirect destination.

The root cause is a TOCTOU (Time-of-Check Time-of-Use) flaw: MLflow validates the webhook URL at registration time to ensure it resolves to a public IP, but during the actual test request, it blindly follows redirects to private addresses. An attacker registers a webhook pointing to a server they control, then configures that server to redirect requests to the AWS/GCP/Azure metadata service at 169.254.169.254. The metadata service responds with the instance's IAM credentials — which typically carry broad cloud-wide permissions.

WatchTowr Intel's global honeypot network detected active exploitation scanning within hours of the CVE's publication on August 17. With a trivially-exploitable attack path requiring no authentication, CVE-2026-64849 represents an acute threat to any organization running internet-accessible MLflow infrastructure as part of their AI/ML operations — a rapidly growing segment of enterprise deployments.

🎓 For beginners: MLflow is a popular tool that helps AI teams organize their experiments. This bug lets a hacker tell MLflow "test this link," but they set up that link to secretly redirect MLflow's server to look up cloud master keys stored at a special internal address (169.254.169.254) that only the cloud server itself is supposed to access. It's like asking a messenger to deliver a package to address A, which then quietly sends them to the bank vault — the messenger brings back the vault key. Using those cloud credentials, the attacker can then access or delete data across the victim's entire cloud account.
CVE-2026-64849 · CVSS: 9.3/10 — Critical severity, unauthenticated network-exploitable SSRF enabling cloud credential theft.

DeadLock Ransomware Uses Polygon Smart Contracts to Make Extortion Infrastructure Resistant to Takedown

▶ Full analysis & beginner explanation

DeadLock is a Rust-based ransomware operation that has made a deliberate architectural choice to build its extortion infrastructure on decentralized technologies specifically to resist law enforcement disruption. Rather than hosting its command-and-control addresses on conventional servers or dark-web .onion domains (both of which can be seized or sinkholed), DeadLock stores C2 URLs as data within smart contracts on the Polygon blockchain. Any infected machine retrieves this data by making a public eth_call RPC request — no wallet, no special access, no domain to seize.

Victim communications are routed through Session, an onion-routed decentralized messaging network, eliminating the need for centralized chat servers. Stolen data is hosted on Wasabi cloud storage. Together, these three layers — blockchain-backed infrastructure discovery, onion-routed communications, and decentralized file hosting — create a recovery ecosystem that can survive takedowns of individual components without losing the ability to extort victims.

Microsoft observed DeadLock being deployed by affiliates of the established Lynx and INC ransomware ecosystems, suggesting DeadLock functions as a ransomware-as-a-service (RaaS) platform available to experienced operators who want more resilient infrastructure. With 80+ European victims across diverse industry sectors, the operation is growing. This blockchain-backed C2 model, if adopted more broadly, could significantly complicate law enforcement's ability to disrupt ransomware operations through the infrastructure takedowns that have historically been effective (e.g., LockBit, Hive).

🎓 For beginners: Traditional ransomware operations have a weakness: their "command center" (a website or server that controls the malware) can be seized by police, like raiding a criminal headquarters. DeadLock solved this by hiding its command center address inside a public blockchain — a permanent, uncensorable record that no government can seize. It's like writing your criminal organization's phone number on a public monument that no one can erase. Law enforcement can arrest individuals, but the infrastructure itself remains operational.

💡 Today I Learned: MFA Fatigue ▶
MFA fatigue (also called push bombing) is an attack where criminals repeatedly send multi-factor authentication approval requests to a victim's phone until the person — overwhelmed, confused, or simply not paying attention — accidentally taps "Approve." Unlike traditional phishing, no fake website is involved: the attacker simply hammers the legitimate authentication system with dozens or hundreds of real push notifications. Today's Azure breach by "TheHatman" combined password spraying (to get the correct password) with MFA fatigue (to bypass the second factor), defeating an organization's entire multi-factor authentication protection without exploiting any software vulnerability. The defense is straightforward: replace push-notification MFA with phishing-resistant alternatives like FIDO2 hardware security keys or passkeys, which require physical interaction and cannot be beaten by push flooding.
📖 Glossary: SSRF · GraphQL · APT · TOCTOU · Babuk · Password Spraying ▶
SSRF — Server-Side Request Forgery: a vulnerability where an attacker tricks a server into making HTTP requests to internal services on their behalf, bypassing network restrictions and firewall rules that protect internal infrastructure.
GraphQL — A flexible API query language and runtime developed by Meta that lets clients specify exactly the data they need; it is increasingly targeted by attackers when authorization controls are applied inconsistently across deeply nested query resolvers.
APT — Advanced Persistent Threat: a highly skilled, well-resourced threat actor — often nation-state-sponsored — that conducts long-term, stealthy intrusion campaigns against specific high-value targets rather than opportunistic mass attacks.
TOCTOU — Time-of-Check to Time-of-Use: a race condition vulnerability where a security validation check is bypassed by changing the conditions being checked between the moment they are verified and the moment the validated action is actually executed.
Babuk — A ransomware family whose complete source code was leaked publicly in 2021, enabling any threat actor to build custom variants; widely used as the basis for new ransomware strains, including the payload deployed in the VMware vCenter campaign today.
Password Spraying — An attack technique that tries a small set of commonly-used or previously-breached passwords against a very large number of user accounts simultaneously, deliberately staying below per-account lockout thresholds to avoid triggering account protection mechanisms.
