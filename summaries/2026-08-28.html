Gitea CVE-2026-60004 (CVSS 9.8): Critical RCE Exploited to Deploy Cryptominers — CISA Deadline Today
🔍 What happened: Attackers are actively exploiting CVE-2026-60004, a CVSS 9.8 remote code execution flaw in Gitea that lets any user with repository write access plant a malicious git hook via the diffpatch endpoint and execute arbitrary shell commands as the Gitea service account—real-world attacks have been deploying cryptomining malware on self-hosted instances.
👤 Who's affected: Any organization running a self-hosted Gitea instance prior to version 1.27.1, particularly those with open registration enabled (which allows unauthenticated attackers to obtain write access by simply registering an account and creating a repository).
✅ What to do: Update Gitea to version 1.27.1 immediately, disable open self-registration, audit all existing repositories for unauthorized git hooks (check .git/hooks/), and restrict Gitea's service account privileges using the principle of least privilege.
🎯 ATT&CK: [Execution] T1059.004 · Command and Scripting Interpreter: Unix Shell
Attackers abuse Gitea's diffpatch endpoint to install a malicious git hook that executes attacker-controlled shell commands under the Gitea service account, enabling cryptominer deployment and potential further lateral movement.
▶ Full analysis & beginner explanation

Gitea is an open-source self-hosted Git service widely used by development teams who want GitHub-like functionality without relying on cloud providers. CVE-2026-60004 turns the platform's git hooks feature—a legitimate automation mechanism—into a remote code execution weapon. The vulnerability lives in the diffpatch endpoint, which improperly handles user-supplied content before passing it to hook execution, allowing any repository write accessor to plant executable code in the server's hook directory.

The attack surface is particularly alarming for instances with open registration: an attacker needs no prior access at all. They can register an account, create a repository, exploit the flaw, and begin executing commands on the server within minutes. CISA added the flaw to its KEV catalog on August 25 with a remediation deadline of today, August 28, for federal civilian agencies.

Observed payloads have been cryptominers, but the same technique could trivially deliver a backdoor, data exfiltrator, or ransomware dropper. Any organization hosting internal code, CI/CD pipelines, or sensitive repositories on an unpatched Gitea instance should treat this as an emergency.

🎓 For beginners: Gitea is like a private version of GitHub that companies run on their own servers to store code. Git hooks are little scripts that run automatically when code is pushed—think of them like a burglar alarm that triggers when someone enters. This bug lets an attacker secretly install a malicious "alarm script" that instead of alerting anyone, runs the hacker's own code on the server whenever triggered.

Cisco ASA & FTD CVE-2026-20349 (CVSS 8.6): Unauthenticated Remote DoS Exploited Against VPN Infrastructure
🔍 What happened: Cisco confirmed active exploitation of CVE-2026-20349, a high-severity flaw in Cisco Secure Firewall ASA and FTD that lets unauthenticated attackers crash VPN-enabled devices by sending a single crafted HTTP request to the Remote Access SSL VPN listener, causing the device to reload and knocking all VPN connectivity offline.
👤 Who's affected: Any organization running Cisco ASA or FTD software with remote-access services enabled—including SSL VPN, IKEv2 remote access VPN with client services, or Zero Trust Network Access—on ASA 9.16 through 9.24 or FTD 7.0 through 10.0 without the available hot-fix patches applied.
✅ What to do: Apply Cisco's hot-fix releases for your specific ASA or FTD version immediately—no workarounds exist; rate-limit inbound connections to VPN endpoints and monitor for repeated device reloads as an active exploitation indicator.
🎯 ATT&CK: [Impact] T1499.004 · Endpoint Denial of Service: Application or System Exploitation
Unauthenticated attackers crash Cisco ASA/FTD devices by sending malformed HTTP packets to the SSL VPN listener, knocking firewall and VPN infrastructure offline and disrupting remote workforce connectivity or security perimeter controls.
▶ Full analysis & beginner explanation

While CVE-2026-20349 is a Denial of Service vulnerability rather than remote code execution, its strategic impact should not be underestimated. Cisco ASA and FTD devices are enterprise-grade firewalls and VPN concentrators; knocking them offline means cutting all remote workforce connectivity, disabling network security enforcement, and potentially impacting business operations across an entire organization with a single malformed packet from any internet address.

The vulnerability stems from insufficient error checking when processing HTTP requests in the Remote Access VPN service. An attacker sends a crafted HTTP request to the SSL listen socket and the device reloads—this can be repeated indefinitely to keep the device in a crash loop. Cisco PSIRT confirmed exploitation in the wild and released hot-fix patches for all supported version lines; there are explicitly no configuration-level workarounds.

For organizations that have not yet patched, defenders should monitor Cisco device syslog for rapid reload events and consider temporarily geo-blocking inbound VPN connections from regions where exploitation activity has been observed. Cisco's PSIRT advisory includes version-specific hot-fix filenames for each affected release.

💡 Today I Learned: Dwell Time ▶
Dwell time is the gap between when attackers first gain access to a network and when they are detected—and the Nevada attack's 102-day dwell is unfortunately not unusual, as the industry average has historically hovered between 60 and 200 days depending on the sector. Attackers use this time to quietly map the network, steal credentials, install persistent backdoors, and identify high-value targets like backup systems—all before anyone realizes something is wrong. Reducing dwell time is one of the highest-leverage investments a security team can make, because the shorter the attacker's window, the less damage they can do before being ejected.
📖 Glossary: Malvertising · Dwell Time · Trojanized Software · Cryptojacking · DoS · Hot Fix ▶
Malvertising — The use of malicious online advertisements or spoofed vendor websites to distribute malware to unsuspecting users, often appearing identical to legitimate software download pages.
Dwell Time — The period between an attacker's initial network compromise and when they are detected or choose to deploy their payload, during which they move laterally and prepare for maximum impact.
Trojanized Software — Legitimate software that has been secretly modified to include malware, typically distributed through fake vendor websites or compromised update channels to exploit user trust.
Cryptojacking — The unauthorized use of a victim's computing resources to mine cryptocurrency, typically deployed silently through exploited vulnerabilities or malicious code, stealing CPU cycles and electricity.
DoS — Denial of Service — an attack that makes a system, service, or network resource unavailable by overwhelming it with traffic or exploiting a vulnerability to cause crashes.
Hot Fix — An emergency software patch released outside a vendor's normal update cycle to address a critical or actively exploited security flaw, requiring immediate deployment rather than waiting for the next scheduled release.
