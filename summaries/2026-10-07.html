Critical FortiMail Zero-Day CVE-2026-104286 Exploited in the Wild — CISA Remediation Deadline Today
🔍 What happened: Fortinet disclosed CVE-2026-104286 (CVSS 9.8), a path traversal and NULL-byte injection flaw in FortiMail that lets unauthenticated remote attackers write arbitrary files to the server, with active exploitation confirmed and CISA's federal remediation deadline falling today.
👤 Who's affected: Organizations running FortiMail versions 7.2.0–7.2.9, 7.4.0–7.4.8, 7.6.0–7.6.6, or 8.0.0–8.0.1 — primarily enterprises using Fortinet's email security gateway for filtering and protection.
✅ What to do: Upgrade immediately to FortiMail 7.2.10, 7.4.9, 7.6.7, or 8.0.2; if patching is not immediately possible, restrict access to the management interface and hunt for unexpected files written to the server filesystem.
🎯 ATT&CK: [Persistence] T1505.003 · Server Software Component: Web Shell
The arbitrary file write capability allows attackers to drop a web shell onto the FortiMail server, creating persistent access that survives reboots and evades detection as legitimate server files.
▶ Full analysis & beginner explanation

CVE-2026-104286 combines two weaknesses: improper path restriction (CWE-22) and inadequate NULL byte handling (CWE-158). When an attacker crafts an HTTP request with a NULL byte inserted into the path, FortiMail's parser truncates the string at that point, stripping away safety checks and allowing the attacker to write files to arbitrary locations on the server filesystem.

The attack vector is as simple as sending a specially crafted HTTPS request — no credentials required, no user interaction needed. Once an attacker can write arbitrary files, the practical outcome is remote code execution: they plant a web shell or overwrite a configuration file to execute commands. Threat actors have already confirmed this path in the wild, deploying backdoors on compromised FortiMail appliances.

Fortinet patched the vulnerability in forked version lines released this week. CISA added the flaw to its Known Exploited Vulnerabilities catalog and set an October 4 deadline for Federal Civilian Executive Branch agencies — that deadline has passed, indicating the threat is real and persistent.

🎓 For beginners: Imagine your email security system has a locked filing cabinet. The path traversal flaw is like tricking the lock mechanism by inserting a key with a hidden notch — the lock thinks it's locking, but the notch bypasses the mechanism. The attacker can then put whatever documents (malicious code) they want into the cabinet, and the server will later run them without question.

▶ Full analysis & beginner explanation

Warlock emerged in mid-2025 exploiting zero-day flaws in Microsoft SharePoint Server collectively called "ToolShell." The group's intrusion chain is methodical: first, they exploit SharePoint to write a web shell into the LAYOUTS directory; second, they harvest the SharePoint farm's ASP.NET machine keys — secret cryptographic values that, once obtained, allow crafting a validly signed payload that executes code inside the SharePoint application pool; third, they pivot into internal networks.

The most technically novel element of Warlock's 2026 campaign is the BYOVD step. Before deploying ransomware, the group imports a known-vulnerable but legitimately code-signed kernel driver. Because Windows trusts the driver's signature, security software cannot block it from loading. Once running at kernel level, it terminates endpoint protection processes from below — a place no user-space security tool can defend. Velociraptor, a legitimate incident-response tool, is then repurposed as Warlock's command-and-control framework.

The targeting pattern — Portuguese- and Spanish-speaking critical infrastructure — suggests geopolitical intelligence objectives alongside financial extortion, a hallmark of Chinese state-affiliated operations.

💡 Today I Learned: BYOVD (Bring Your Own Vulnerable Driver) ▶
BYOVD is a technique where attackers load a legitimate but known-vulnerable driver into Windows to operate at the kernel level — the deepest layer of the operating system — allowing them to kill security software from below where no antivirus can fight back. Because the driver carries a valid code-signing certificate from a real vendor, Windows loads it without complaint, making blocklists the primary defense. Microsoft publishes a Vulnerable Driver Blocklist updated via Windows Update, and WDAC (Windows Defender Application Control) policies can enforce it, but many organizations don't keep these enforced — leaving the door open for groups like Warlock to walk straight through antivirus protection before deploying ransomware.
📖 Glossary: MCP · BYOVD · FCEB · C2 · CI/CD ▶
MCP — Model Context Protocol: an open standard that lets AI coding assistants and chatbots securely connect to external tools, APIs, and data sources, enabling them to take actions on behalf of developers.
BYOVD — Bring Your Own Vulnerable Driver: a technique where attackers import a legitimately signed but exploitable kernel driver to gain elevated privileges and disable security software from the OS kernel level.
FCEB — Federal Civilian Executive Branch: the U.S. federal agencies (excluding military and intelligence) subject to CISA's Binding Operational Directives, including mandatory KEV remediation deadlines.
C2 — Command and Control: the infrastructure (servers, protocols, or channels) attackers use to remotely issue commands to and receive data from compromised systems inside a victim network.
CI/CD — Continuous Integration / Continuous Deployment: automated software build and delivery pipelines that, when misconfigured, can expose sensitive secrets (API keys, credentials) that attackers harvest for initial access.
