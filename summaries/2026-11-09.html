Ivanti Patches Two More Zero-Days in Connect Secure Attack Chain, Root Access Possible
🔍 What happened: Two new Ivanti Connect Secure VPN zero-days (CVE-2026-111357 and CVE-2026-118527) have been exploited in the wild as part of a three-bug chain enabling root-level access on enterprise VPN appliances.
👤 Who's affected: Organizations running Ivanti Connect Secure before versions 25.1.1.3 or 22.8R2.6; administrators who patched in October for CVE-2026-104935 are still exposed to these two newer CVEs.

🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
Attackers exploit Ivanti's public-facing VPN appliance by chaining three CVEs — authentication bypass, privilege escalation (CWE-306 missing auth for critical function), and predictable file placement — to achieve persistent root access on the network perimeter device without valid credentials.

This is the third and most dangerous chapter in an ongoing Ivanti Connect Secure exploit saga. The original flaw (CVE-2026-104935), an authentication bypass rated 8.8, was patched on October 13. But Volexity researchers discovered that attackers had already pivoted to two additional flaws in the same codebase: CVE-2026-111357, a "missing authentication for critical function" bug (CWE-306), and CVE-2026-118527, which lets authenticated attackers write files to predictable paths. When chained, all three give an unauthenticated remote attacker root shell access on the VPN appliance.

CISA added both CVEs to its Known Exploited Vulnerabilities (KEV) catalog on October 30, citing confirmed in-the-wild exploitation. The federal civilian agency deadline for CVE-2026-111357 was November 2; for CVE-2026-118527 it is November 13, 2026. Organizations that patched in October for CVE-2026-104935 but have not yet updated to 25.1.1.3 or 22.8R2.6 remain fully exposed to this chain.

Indicators of compromise include unexpected outbound connections, unauthorized VPN sessions, new administrator accounts, and modified configuration files on the appliance. Ivanti's Integrity Checker Tool (ICT) can flag unauthorized changes to firmware. Any organization that may have been compromised before patching should treat the appliance as untrusted and conduct a full incident-response investigation.

Hackers Exploit OpenSSH "sshole" Flaw Within Hours of Disclosure, Gaining Root Access on Alpine Linux Honeypot
🔍 What happened: CVE-2026-123158, nicknamed "sshole," is an OpenSSH password authentication bypass affecting systems using musl libc (most notably Alpine Linux) without PAM, confirmed exploited on a honeypot within hours of public disclosure.
👤 Who's affected: Systems running OpenSSH prior to 10.6p2 on Alpine Linux or any distribution using musl libc — particularly prevalent in Docker container environments and cloud microservices built on Alpine base images.
✅ What to do: Upgrade to OpenSSH 10.6p2 (or the branch-specific Alpine patched package) and restart sshd; audit logs for unexpected "Accepted password" entries on accounts configured to reject passwords.
🎯 ATT&CK: [Credential Access] T1556 · Modify Authentication Process
The vulnerability exploits a flaw in sshd's password handling where oversized input interacts with musl libc's crypt() function in a way that bypasses credential validation — directly subverting how the system verifies identity, the core of ATT&CK's T1556 technique.
▶ Full analysis & beginner explanation

The vulnerability stems from how OpenSSH's sshd interacts with musl libc — a lightweight C library used in Alpine Linux and many Docker containers — when password authentication is enabled but PAM (Pluggable Authentication Modules) is not. The root cause: when the stored password hash is shorter than 4 characters (which occurs on locked accounts configured via "*" or "!" in /etc/shadow), sending an unusually long password input causes the comparison to succeed, bypassing authentication entirely. OpenSSH 10.6p2 addresses this by validating hash length before the comparison takes place.

Alpine Linux is by far the most popular base image for Docker containers — the majority of containerized services, CI/CD runners, web servers, and microservices deployed to cloud environments use Alpine. If sshd is enabled and password authentication is on, those containers could be internet-exposed or reachable from compromised services on the same network. Exploitation on a public honeypot within hours of disclosure confirms threat actors have weaponized the vulnerability and are actively scanning. While CISA has not yet added this to KEV as of this writing, the speed of exploitation makes it urgent.

🎓 For beginners: SSH is the standard secure way to log into a remote server via the terminal. This flaw is like a combination lock that opens if you just spin the dial long enough — the combination itself stops mattering. Alpine Linux is what most Docker images are built on; if you've ever used a Docker image starting with "FROM alpine," your app might be running affected software. Upgrade any Alpine-based containers that expose SSH, and do it now.
CVE-2026-123158 · CVSS: 8.1/10 — Password authentication bypass via oversized input interacting with musl libc's crypt() function; affects OpenSSH sshd without PAM on musl-based Linux systems; patched in 10.6p2.

▶ Full analysis & beginner explanation

November 2026 is one of Google's largest Android patch cycles in recent memory, covering 216 CVEs across the Android Framework, System, Kernel, and vendor components. The marquee flaw, CVE-2026-58868, resides in the Android Framework layer and is rated Critical because it enables remote code execution without requiring any action from the target — a "zero-click" vulnerability. The attacker targeted DreamHost's File Manager to harvest FTP/SFTP credentials and active webmail session tokens from an application storing authentication material in an accessible way — a textbook case of credential collection via insecure credential exposure in a web-hosted management tool.

DreamHost's browser-based File Manager lets customers manage their hosting files without a desktop FTP client. SonicWall SSLVPN CVE-2026-19868: SAML Authentication Bypass Circumvents MFA — In CISA KEV
🔍 What happened: CVE-2026-19868 is an authentication enforcement flaw in SonicOS SSLVPN that allows a user with credentials for an alternate authentication method to bypass SAML controls — including SAML-enforced multi-factor authentication — and gain VPN access without completing the full MFA flow.
👤 Who's affected: Organizations using SonicWall firewalls with SSLVPN enabled in SAML authentication mode; CISA has flagged this as a Known Exploited Vulnerability, indicating active use in attacks against real-world networks.
✅ What to do: Apply the SonicWall PSIRT patch when published, disable any alternate login methods that bypass SAML on the SSLVPN portal, and restrict VPN access to known-IP allowlists while the fix is pending.
🎯 ATT&CK: [Initial Access] T1133 · External Remote Services
This vulnerability abuses the SonicWall SSLVPN's external remote access service, allowing attackers to bypass authentication and enter the corporate network through the VPN as if they were a legitimately authenticated employee — directly targeting the boundary control organizations rely on for perimeter defense.
▶ Full analysis & beginner explanation

SAML (Security Assertion Markup Language) is the enterprise standard for single sign-on and federated MFA. Organizations configure SonicWall SSLVPN to use SAML precisely to enforce MFA — requiring a hardware token, mobile authenticator, or biometric in addition to a password. CVE-2026-19868 (CWE-308: Use of Single-Factor Authentication Where Multi-Factor Is Required, CVSS 7.5) undermines this entirely: an attacker who possesses or guesses any alternate credential accepted by the VPN service can skip the SAML/MFA requirement and log directly in.

MFA bypass vulnerabilities on VPN gateways are especially prized by ransomware operators and nation-state groups because VPN access typically leads directly to the internal corporate network, bypassing all perimeter security controls. CISA's KEV designation confirms this is not theoretical — real attackers are actively using it. No public patch details have been disclosed as of Nov 9, raising immediate urgency for interim mitigations: disabling alternate authentication paths that don't route through SAML, and setting up geo-based or IP-based access restrictions on the SSLVPN portal.

🎓 For beginners: MFA (Multi-Factor Authentication) is the extra step — like a code texted to your phone — that protects accounts even if someone steals your password. SAML is how corporate systems enforce that extra step centrally. This vulnerability is like a secret back door to the office that bypasses the security guard who checks for your ID and phone code together — attackers can walk straight in. If your company uses SonicWall for VPN access, ask your IT team whether this applies and what mitigations are in place right now.

💡 Today I Learned: Zero-Click Exploit ▶
A zero-click exploit is a type of cyberattack that compromises a device without the target ever needing to tap, click, or open anything — the malicious code runs automatically when a device receives a specially crafted message, image, or data packet. These are especially dangerous because all the conventional "don't click suspicious links" advice offers zero protection, making them valuable for nation-state surveillance tools like Pegasus and high-end criminal operations willing to pay premium prices. Historically, zero-click bugs have been found in messaging apps (iMessage, WhatsApp), image rendering libraries, and operating system components that process incoming data before any user sees it — the Android Framework flaw patched this month is a prime example.
📖 Glossary: SAML · musl libc · Residential Proxy · BYOD · Zero-Click ▶
SAML — Security Assertion Markup Language; an open standard that lets a single identity provider (like Azure AD or Okta) authenticate users across multiple services using a trust token, enabling corporate single sign-on and centralized MFA enforcement.
musl libc — A lightweight alternative to the standard C library (glibc) used in minimal Linux distributions like Alpine; its smaller codebase makes it popular for containers but can introduce subtle behavioral differences from glibc that expose vulnerabilities when software assumes glibc semantics.
Residential Proxy — An intermediary server that routes internet traffic through the IP address of a real home device (often an infected phone or PC), making malicious traffic appear to come from a legitimate consumer internet connection and bypassing blocks that target data-center IPs.
BYOD — Bring Your Own Device; a corporate policy permitting personal devices for work tasks, and also the name of a ransomware group that exploits weakly managed personal devices to pivot into corporate networks.
Zero-Click — An attack class requiring no interaction from the victim; the exploit fires automatically upon receipt of a malicious packet, message, or media file, leaving users with no behavioral defenses against compromise.
