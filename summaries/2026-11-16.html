Microsoft Patches Actively Exploited Outlook Zero-Day CVE-2026-124194 That Steals NTLM Hashes Without User Interaction
🔍 What happened: Microsoft's November Patch Tuesday fixed CVE-2026-124194, an Outlook spoofing zero-day already exploited in the wild that forces Outlook to auto-connect to an attacker-controlled server when a crafted .msg file is received — sending the victim's NTLM credential hash without any user click required.
👤 Who's affected: All Windows Outlook users in organizations relying on NTLM authentication; enterprise environments where NTLM is used for internal service authentication face the highest risk of credential relay attacks.
✅ What to do: Apply November 2026 Patch Tuesday immediately (federal deadline: Nov 24 per CISA KEV); enable SMB signing; disable NTLMv1; consider blocking outbound SMB (port 445) to external hosts at the perimeter.
🎯 ATT&CK: [Credential Access] T1187 · Forced Authentication
The exploit triggers Outlook to automatically initiate an SMB or HTTP authentication request to an attacker-controlled host, involuntarily sending the victim's NTLMv2 hash — which can then be cracked offline or relayed to authenticate against internal services.
▶ Full analysis & beginner explanation

The CVSS score of 6.5 (Moderate) dramatically understates this vulnerability's real-world impact. While it doesn't allow direct remote code execution, stolen NTLM hashes are highly actionable: an attacker on the same network can immediately relay them to authenticate to file shares, Exchange servers, or domain controllers (pass-the-hash). Even off-network, modern GPU clusters can crack NTLMv2 hashes for weak-to-medium-strength passwords in minutes to hours.

The "no user interaction" aspect makes this especially dangerous in targeted phishing scenarios. An attacker need only send a malicious .msg file attachment — the moment Outlook processes it, authentication fires automatically. This follows a lineage of similar Outlook forced-auth bugs (CVE-2023-23397 being the most notable prior example) that have been weaponized by nation-state actors.

CISA's addition to the KEV catalog with the November 24 federal deadline signals that exploitation is active and not theoretical. Organizations should treat this as a priority even if they applied Patch Tuesday — confirm the patch is deployed everywhere, including RDS/Citrix environments where Outlook is hosted.

🎓 For beginners: When you log into a Windows computer or company network, Windows stores a scrambled version of your password called an "NTLM hash." This bug tricks your Outlook email program into automatically sending that hash to a hacker's server — without you clicking anything. The hacker can then use your hash to log into other company systems pretending to be you, or they can try to unscramble it to get your actual password. It's like someone stealing your house key impression without you knowing.
CVE-2026-124194 · CVSS: 6.5/10 — Marked Moderate but CISA-flagged as actively exploited; real-world impact significantly higher due to credential relay potential

Google Chrome Zero-Day CVE-2026-125350: Use-After-Free in XML Component Actively Exploited in the Wild
🔍 What happened: Google patched a use-after-free bug in Chrome's XML processing component (CVE-2026-125350) on November 9 after CISA confirmed it was being actively exploited; a crafted malicious webpage can trigger memory corruption and achieve remote code execution within the browser's renderer process.
👤 Who's affected: All users of Google Chrome prior to version 157.0.8103.50 on all platforms; Chromium-based browsers (Microsoft Edge, Brave, Opera) are also affected until vendors ship their own updates based on the upstream patch.
✅ What to do: Update Chrome immediately to 157.0.8103.50 or later; enterprise admins should verify managed browser policies force rapid update delivery; Edge/Brave/Opera users should check for available updates.
🎯 ATT&CK: [Execution] T1203 · Exploitation for Client Execution
The UAF vulnerability in Chrome's XML parser allows a malicious webpage to execute arbitrary code inside the browser's renderer sandbox, representing the first step toward full system compromise if chained with a sandbox-escape bug.
▶ Full analysis & beginner explanation

This is Chrome's eighth zero-day of 2026 — a pace that reflects both the browser's enormous attack surface and the intensity of research by state-sponsored and criminal actors targeting it. Use-after-free bugs are among the most exploitable memory corruption classes: they occur when a program accesses memory it has already freed, allowing attackers to place malicious data at that memory location and have the program execute it as code.

The XML component is particularly attractive to attackers because XML parsing is complex, widely used (SVG images, XHTML content, and many web APIs rely on it), and difficult to sandbox away from main rendering logic. Active exploitation prior to the patch suggests a sophisticated actor discovered this bug and was using it in targeted attacks before Google was aware of it.

🎓 For beginners: When you visit a website, your browser processes lots of different types of content — including a data format called XML, which is used for things like images and structured data. This bug is in the part of Chrome that handles XML. When Chrome reads certain specially-crafted XML content on a malicious website, it can be tricked into running the attacker's code on your computer. Just visiting a malicious webpage — without downloading anything — could be enough to trigger it.

💡 Today I Learned: NTLM Relay Attack ▶
An NTLM relay attack lets hackers authenticate to systems as you without ever knowing your actual password — they simply intercept your NTLM credential hash and immediately forward it to another target server in real time. The key insight is that NTLM authentication doesn't verify the full chain of trust: if an attacker sits between you and a service, they can relay your authentication handshake to a completely different service and gain access as you. Today's Outlook zero-day (CVE-2026-124194) demonstrates exactly this: it forces your email client to auto-authenticate to an attacker's server, handing them your hash to relay into your company's file shares, internal web apps, or even domain controllers. Defenders stop relay attacks by enforcing SMB signing (which ties each authentication to a specific session), requiring EPA (Extended Protection for Authentication), and disabling legacy NTLMv1 — all of which break the relay chain even if the hash is captured.
📖 Glossary: UAF · RaaS · Supply Chain Attack · Firmware Implant · Authentication Bypass ▶
UAF (Use-After-Free) — A memory corruption bug where a program continues to use a memory pointer after freeing that memory; exploiting it lets attackers place malicious data at the freed location and have the program execute it as code.
RaaS (Ransomware-as-a-Service) — A criminal business model where ransomware developers license their malware to "affiliate" operators who carry out attacks, splitting the ransom proceeds — mirroring legitimate software-as-a-service economics.
Supply Chain Attack — An attack that compromises a less-secure element in the production or distribution chain of a product — such as a hardware manufacturer, software vendor, or IT provider — to reach downstream victims who trust that element.
Firmware Implant — Malicious code or hardware inserted into a device's low-level firmware or physical components during manufacturing or distribution, making it deeply persistent and invisible to conventional antivirus and OS-level security tools.
Authentication Bypass — A vulnerability that allows an attacker to skip or circumvent the normal login/authentication process and gain access to a system or resource without providing valid credentials.
