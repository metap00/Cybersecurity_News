Google Issues Emergency Chrome Update for Eighth Actively Exploited Zero-Day of 2026 (CVE-2026-125350)
🔍 What happened: Google patched a use-after-free vulnerability in Chrome's XML component (CVE-2026-125350) that is being actively exploited in the wild and has been added to CISA's Known Exploited Vulnerabilities catalog.
👤 Who's affected: All users running Chrome below version 157.0.8103.50 on Windows, macOS, and Linux are vulnerable to arbitrary code execution via a malicious web page.
✅ What to do: Update Chrome immediately to version 157.0.8103.50 or later; federal agencies must patch by November 24, 2026 per CISA's KEV directive.
🎯 ATT&CK: [Execution] T1203 · Exploitation for Client Execution
Attackers exploit this browser-level UAF bug to execute shellcode in the context of the Chrome renderer process, turning a drive-by page visit into code execution on the victim's machine.
▶ Full analysis & beginner explanation

CVE-2026-125350 is a use-after-free (UAF) flaw in Chrome's handling of XML document parsing. When Chrome frees a memory object but continues using a reference to that freed memory, an attacker can craft a web page with a specially structured XML payload that causes the stale pointer to reference attacker-controlled data, leading to arbitrary code execution inside the renderer process.

This is Chrome's eighth zero-day patched in 2026 — an unusually high count that reflects both the browser's attack-surface breadth and the sustained commercial demand for browser exploits from nation-states and criminal groups. CISA added this to its KEV catalog the same day Google published the advisory, confirming active exploitation across federal and commercial targets.

Google has not disclosed the identity of the threat actors exploiting this flaw, the scale of the campaign, or specific indicators of compromise. The fix is available through Chrome's automatic update mechanism; users can verify their version at chrome://settings/help.

🎓 For beginners: Chrome is constantly loading web pages that are written by strangers. This bug meant that a malicious web page could trick Chrome into running the attacker's code on your computer without you doing anything beyond visiting the page. Google has already pushed a fix — just restart Chrome and let it update.
CVE-2026-125350 · CVSS: 8.8/10 — High-severity browser exploit enabling remote code execution through a crafted web page, with active in-the-wild exploitation confirmed by Google and CISA.

OPTIMJACK: Malicious JavaScript Injected via Optimizely CDN, Hitting 178+ Organizations Including CNN, Zoom, BBC, Salesforce
🔍 What happened: Attackers placed a crypto-clipper and card-skimmer payload in Optimizely's per-customer "Project JavaScript" field, causing cdn.optimizely.com to serve malicious code to visitors of at least 178 major organizations since November 16, 2026.
👤 Who's affected: Visitors to sites using Optimizely's A/B testing platform — including CNN, Zoom, BBC, Salesforce, GitLab, Fox News, and American Eagle — may have had their clipboard and payment data harvested.
✅ What to do: Site owners should audit their Optimizely Project JavaScript for any reference to the domain 1688360.cc and remove any code they did not author; end users on affected sites should monitor payment accounts and avoid cryptocurrency transactions until further notice.
🎯 ATT&CK: [Initial Access] T1195.002 · Supply Chain Compromise: Compromise Software Supply Chain
By injecting malicious JavaScript into Optimizely's trusted CDN delivery pipeline, the attacker piggybacks on the implicit trust organizations place in their A/B testing vendor's scripts, bypassing CSP and browser security warnings entirely.
▶ Full analysis & beginner explanation

The OPTIMJACK campaign exploited the fact that Optimizely allows customers to inject arbitrary JavaScript into their per-project configuration. An unauthorized party modified these project-level code fields, causing the legitimate Optimizely CDN domain (cdn.optimizely.com) to deliver a two-stage payload: first loading a secondary script from the domain 1688360.cc, which then deployed a crypto-clipboard hijacker (swapping copied wallet addresses) and a card-skimming module targeting payment forms.

The attack was first detected by security researcher Scott Helme of Report URI, who scanned 1,611 Optimizely snippets and found 188 infected, belonging to 178 distinct organizations. Because the malicious code was served from cdn.optimizely.com — a domain that virtually all security tools and CSPs trust — conventional defenses did not block it. StepSecurity confirmed at least 186 infected sites and noted the attacker used a consent-manager loading chain (cdn.cookielaw.org → cdn.optimizely.com → 1688360.cc) to maintain stealth.

Optimizely began cleaning files on the evening of November 16, but the attack was still being reported as ongoing as of this writing. The company has not yet published a formal security advisory. Mandiant is reported to be assisting with the investigation. The specific method by which the attacker gained write access to customer Project JavaScript fields — whether via compromised credentials, an Optimizely admin-panel vulnerability, or insider access — has not been confirmed.

🎓 For beginners: Many major websites use a service called Optimizely to run A/B tests (showing different versions of a page to different visitors). That service runs a JavaScript file on the page, and attackers slipped malicious code into that file. Because the file came from a trusted Optimizely server, the browser ran it without question — the same as if the company itself had placed it there.
No single CVE assigned · CVSS: N/A — Supply chain attack with broad blast radius; severity is based on the number of affected organizations and the sensitive nature of the harvested data (payment cards, cryptocurrency).

Exploited Outlook Zero-Day CVE-2026-124194 — Crafted Email Silently Steals Windows NTLM Hashes
🔍 What happened: A spoofing vulnerability in Microsoft Outlook (CVE-2026-124194) allows an attacker to send a crafted .msg file that causes Outlook to automatically authenticate to a remote server, leaking the recipient's NTLMv2 hash without any warning or user click.
👤 Who's affected: All Microsoft 365 and Office 2021/2019/2016 users on Windows who have not applied the November 10, 2026 security update are vulnerable to credential theft via a single received email.
✅ What to do: Apply the November 2026 Patch Tuesday update immediately, and enforce outbound SMB (port 445) blocking at the network perimeter as a secondary control against hash relay attacks.
🎯 ATT&CK: [Credential Access] T1187 · Forced Authentication
The crafted .msg file contains a UNC path that Outlook resolves automatically, forcing the victim's Windows host to authenticate to the attacker's SMB server and surrender the NTLMv2 hash, which can then be cracked offline or relayed to other services.
▶ Full analysis & beginner explanation

CVE-2026-124194 is a spoofing vulnerability in Microsoft Outlook's handling of message file (.msg) attachments. When a specially crafted .msg file is delivered to a victim's inbox, Outlook automatically resolves an embedded UNC path (e.g., \\attacker-server\share\file) during preview or rendering. This triggers Windows' NTLM authentication mechanism, sending the user's NTLMv2 hash to the attacker-controlled server without displaying any warning dialog or requiring the user to click anything beyond opening the email.

The stolen NTLMv2 hash can be relayed in an NTLM relay attack against other internal services (Exchange, file shares, Active Directory LDAP) or cracked offline using tools like Hashcat, potentially revealing the user's plaintext password. Microsoft confirmed exploitation in the wild was detected before the November 10, 2026 patch was released, though it has not attributed the attacks to a specific threat actor or disclosed the number of victims. ThreatDefence published a hunting guide with Sigma rules for detecting exploitation attempts.

🎓 For beginners: Windows uses a system called NTLM to prove who you are on a network. This bug tricks Outlook into quietly sending your login credentials to a hacker's server just by receiving a booby-trapped email — no clicking required. The fix is a free Windows update that Microsoft already released on November 10.
CVE-2026-124194 · CVSS: 8.0/10 — Spoofing flaw that enables credential theft via passive email receipt, with active exploitation confirmed by Microsoft prior to patch availability.

Critical Deserialization RCE in Apache Roller (CVE-2026-82384) Allows Unauthenticated Takeover — Patch to 6.1.6
🔍 What happened: A critical deserialization vulnerability in the Apache Roller blogging platform's XML-RPC endpoint (CVE-2026-82384) allows unauthenticated attackers to achieve remote code execution on any exposed instance by sending a crafted XML payload.
👤 Who's affected: Organizations running Apache Roller versions 4.0 through 6.1.5 with the XML-RPC interface exposed — commonly used by universities, government agencies, and media organizations — are at risk of full server compromise.
✅ What to do: Upgrade to Apache Roller 6.1.6 immediately, which disables the vulnerable XML-RPC extension types; if patching is not immediately possible, block port 443/80 access to the /roller-services/xmlrpc endpoint at the WAF or firewall.
🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
The Apache Roller XML-RPC endpoint is reachable without authentication, making it a direct internet-facing attack surface; exploiting the deserialization flaw gives the attacker an OS-level shell on the web server with no prior access required.
▶ Full analysis & beginner explanation

Apache Roller is a Java-based blogging platform used primarily in enterprise and academic settings. Its XML-RPC endpoint, originally designed to allow remote publishing tools (like desktop blog editors) to interact with the platform, deserializes arbitrary Java objects sent in XML payloads. CVE-2026-82384 exploits this by sending a specially crafted serialized payload containing a "gadget chain" — a sequence of legitimate Java class constructors that, when chained together by the deserializer, ultimately executes attacker-specified OS commands.

The flaw is particularly dangerous because it requires no authentication — an attacker with network access to the XML-RPC endpoint gets immediate code execution. Black Duck researchers noted that exploitation requires only a public PoC payload adapted from existing deserialization frameworks like ysoserial. The fix in 6.1.6 removes the ability to deserialize untrusted extension types and disables XML-RPC by default. A secondary deserialization bug (CVE-2026-123374) affecting versions through 6.1.6 was also patched in 6.1.7, so updating directly to 6.1.7 is recommended if available.

🎓 For beginners: Think of "deserialization" as the software equivalent of opening a package: you receive data and unpack it into usable objects. This bug lets an attacker ship a "package" that, when unpacked by Apache Roller, secretly runs their malicious code. Because the unpacking happens automatically on every request, no login or social engineering is needed.
CVE-2026-82384 · CVSS: 9.8/10 — Critical unauthenticated RCE via deserialization; organizations are urged to patch immediately as public exploit tooling makes mass exploitation trivial.

▶ Full analysis & beginner explanation

CVE-2026-123039 is a local privilege escalation flaw in Check Point's Gaia OS, the hardened Linux-based operating system that runs on Check Point's firewall and gateway appliances. The vulnerability resides in the dynamic_server process — a component that handles dynamic routing updates — and allows a user with restricted shell access to escalate to root by exploiting an unsafe system call or configuration that the process runs with elevated privileges.

Check Point confirmed exploitation against roughly 24 customers, suggesting a targeted campaign rather than mass exploitation. Network security appliances are high-value post-compromise targets: once an attacker achieves root on a firewall, they can intercept all traffic flowing through it, modify routing tables, disable logging, implant persistent backdoors in firmware, or pivot deeper into the protected network. The existence of a temporary mitigation (stopping dynamic_server) allows organizations to reduce exposure before fully patching.

With the master key, they can read everything passing through the firewall and even leave a backdoor for future visits.

💡 Today I Learned: CDN-Based Supply Chain Compromise ▶
A CDN-based supply chain compromise occurs when an attacker gains write access to code that is served from a trusted Content Delivery Network domain — a domain that most websites, browsers, and security tools explicitly trust. Because the malicious script is delivered from an authoritative, expected source (e.g., cdn.optimizely.com), standard browser security mechanisms like Content Security Policy and subresource integrity checks fail to block it unless the site owner has explicitly pinned the expected script hash. The OPTIMJACK campaign is a textbook example: by modifying Optimizely's customer-configurable JavaScript field rather than attacking the CDN infrastructure itself, the attacker bypassed CDN-level protections entirely and turned a marketing tool into a weaponized distribution channel reaching millions of visitors across 178+ organizations simultaneously.
📖 Glossary: CDN · Supply Chain Attack · Deserialization · Credential Coercion · OGNL ▶
CDN — Content Delivery Network; a geographically distributed network of servers that caches and delivers website assets (scripts, images, fonts) from locations close to the visitor, improving load times and providing a trusted delivery channel that browsers rarely question.
Supply Chain Attack — An attack that compromises a vendor, software library, or service that the target organization trusts and uses, allowing the attacker to reach many victims simultaneously through a single point of leverage rather than attacking each one individually.
Deserialization — The process of reconstructing a data object from a stored or transmitted byte sequence; when an application deserializes data from an untrusted source without validation, attackers can craft payloads that cause the reconstructed object to execute arbitrary code.
Credential Coercion — A technique that tricks a Windows host into automatically initiating an authentication handshake (typically NTLM) to an attacker-controlled server, surrendering the user's password hash in the process without any user interaction beyond receiving a crafted message.
OGNL — Object-Graph Navigation Language; a Java expression language used in frameworks like Apache Struts and Confluence to access and modify object properties; frequently exploited in RCE attacks when user-supplied OGNL expressions are evaluated without sandboxing (e.g., the original Log4Shell and multiple Confluence vulnerabilities).
