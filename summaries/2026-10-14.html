Attacker Chains Three Ivanti Connect Secure Zero-Days for Root Access — Only Two Patched So Far
🔍 What happened: A threat actor tracked as UTA0576 has been chaining three zero-day vulnerabilities in Ivanti Connect Secure VPN appliances since at least October 3, achieving unauthenticated root access on fully patched devices.
👤 Who's affected: Organizations running Ivanti Connect Secure before version 25.1.3.0 (and older 22.x and 25.1.x branches) that use the VPN appliance as an internet-facing remote-access gateway.
✅ What to do: Upgrade to ICS 25.1.3.0 immediately, review Ivanti's advisory for the unpatched third flaw workaround, and use Volexity's published IoCs to check for signs of lateral movement originating from the VPN device.
🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
UTA0576 exploits chained authentication bypass and privilege escalation flaws in the internet-exposed Ivanti Connect Secure VPN interface to achieve unauthenticated root access with no user interaction required.
▶ Full analysis & beginner explanation

Ivanti disclosed CVE-2026-104935 on October 13, acknowledging that Volexity had observed active exploitation of a three-vulnerability chain in Connect Secure VPN appliances. The chain begins with an unauthenticated HTTP request that bypasses Ivanti's authentication layer, proceeds to execute arbitrary commands, and then escalates privileges to root via a third, as-yet-unpatched local privilege escalation bug. The result is full administrative control over the appliance — including access to all tunneled VPN traffic, stored credentials, and internal network routes.

Volexity attributes the campaign to UTA0576, a suspected nation-state threat actor with a pattern of targeting network edge devices. Exploitation was traced back to October 3, meaning attackers had at least 10 days of undetected access before public disclosure. Only two of the three CVEs have patches available. Ivanti's advisory promises a fix for the third "in the coming weeks." Federal agencies face the most acute exposure, as Ivanti Connect Secure is widely deployed in government environments.

The attack mirrors previous Ivanti zero-day campaigns (CVE-2023-46805 / CVE-2024-21887) that were also exploited by suspected nation-state actors weeks before patches arrived. Organizations should treat any ICS device with internet exposure as potentially compromised and conduct forensic triage regardless of patch status.

🎓 For beginners: Ivanti Connect Secure is essentially a digital doorway that lets employees securely access company networks from home. This attack lets hackers walk right through that doorway without needing a key — by exploiting three bugs in a chain, they can take over the entire door system with administrator privileges and then sneak into the internal network behind it.

Microsoft October 2026 Patch Tuesday Fixes Record 1,411 Flaws — Exploited Windows Shell Zero-Day Among Them
🔍 What happened: Microsoft's October Patch Tuesday — the largest in history — includes a fix for CVE-2026-96951, a Windows Shell Mark-of-the-Web bypass rated CVSS 8.8 that is already being actively exploited in the wild.
👤 Who's affected: All Windows users on any supported Windows version who open files received via email, messaging apps, or the internet, which is effectively all Windows desktops and servers worldwide.
✅ What to do: Apply the October 2026 Patch Tuesday updates immediately — especially CVE-2026-96951; CISA has added it to the KEV catalog with a federal remediation deadline of October 16.
🎯 ATT&CK: [Defense Evasion] T1553.005 · Mark-of-the-Web Bypass
Attackers exploit the Windows Shell flaw to strip the MotW flag from malicious files delivered via phishing or download, letting executables and scripts run without SmartScreen warnings or Protected View activation.
▶ Full analysis & beginner explanation

October 2026's Patch Tuesday is the largest single release in the history of the program, addressing roughly 1,411 CVEs across Windows, Office, Azure, .NET, and dozens of other products. Among them, CVE-2026-96951 stands out as the only confirmed actively exploited zero-day. The flaw exists in Windows Shell's handling of file metadata: when a user downloads a file from the internet, Windows attaches a Zone Identifier attribute (the Mark-of-the-Web) that tells apps like Office and Edge to treat it as untrusted. The bug allows an attacker to craft a malicious file that arrives appearing trustworthy, bypassing SmartScreen warnings and Office Protected View.

The typical attack chain involves a phishing email or malicious download link. When the victim opens the specially crafted file, the shell flaw silently removes or suppresses the MotW flag, causing Windows to treat a dangerous script or executable as if it came from a trusted local source. Microsoft has not publicly attributed the exploitation but CISA's same-day KEV addition suggests active, in-the-wild attacks against real targets.

A second zero-day, CVE-2026-108398, affecting .NET Framework's Windows Defender Application Control enforcement was also disclosed but has not yet been seen exploited. Security teams should prioritize CVE-2026-96951 but plan to patch WDAC within days given the public disclosure risk.

🎓 For beginners: Windows normally puts a digital sticker on files you download from the internet saying "be careful — this came from the web." Programs like Word or Edge see that sticker and show you a warning before running anything. This bug lets hackers make a dangerous file that arrives without that sticker, so Windows trusts it just like a file you created yourself and skips the warning entirely.
CVE-2026-96951 · CVSS: 8.8/10 — High severity; command injection via Windows Shell with local user interaction required, but exploitation is trivial once a victim opens a crafted file.

Critical FortiMail Zero-Day CVE-2026-104286 Actively Exploited — Unauthenticated File Write Leads to Full System Takeover
🔍 What happened: Fortinet disclosed and CISA immediately added CVE-2026-104286 to its Known Exploited Vulnerabilities catalog — a CVSS 9.8 path traversal vulnerability in FortiMail that allows unauthenticated remote attackers to write arbitrary files to the server, leading to full system compromise via deployed web shells and backdoors.
👤 Who's affected: Approximately 2,800 internet-exposed FortiMail deployments running versions 7.2.0–7.2.9, 7.4.0–7.4.8, 7.6.0–7.6.6, and 8.0.0–8.0.1 are at immediate risk.
✅ What to do: Apply Fortinet advisory FG-IR-26-175 patches immediately; if patching is not immediately possible, disable IBE feature support as a temporary workaround and restrict management interface access to trusted IP ranges only.
🎯 ATT&CK: [Persistence] T1505.003 · Server Software Component: Web Shell
Attackers exploit the path traversal to write attacker-controlled PHP or JSP files to web-accessible directories on FortiMail, establishing persistent web shells that survive reboots and provide ongoing command execution and backdoor access.
▶ Full analysis & beginner explanation

CVE-2026-104286 combines a path traversal weakness with improper handling of NULL bytes in HTTP requests — an attacker sends a crafted request that tricks FortiMail into interpreting a path like /mail/../../webroot/shell.php%00 as a valid file destination, writing attacker-supplied content to any location the FortiMail process has write access to. Because FortiMail runs with elevated privileges to process mail for the entire organization, this translates to arbitrary file write across the appliance. Post-exploitation analysis from Fortinet and third-party responders has found web shells, malicious shared libraries injected into running processes, and backdoor SSH keys.

Fortinet published advisory FG-IR-26-175 on October 1 and CISA immediately added the CVE to its KEV catalog, setting a federal remediation deadline of October 4 — indicating that confirmed exploitation was already underway at time of publication. The attack requires no authentication and no user interaction, making it trivially weaponizable. With roughly 2,800 FortiMail hosts exposed to the internet, the blast radius is significant — FortiMail is particularly common in mid-size enterprises and government email environments.

Organizations that cannot patch immediately should treat the mitigation (disabling IBE) as a short-term measure only. The feature disablement does not eliminate all exploitation paths. The Fortinet advisory includes SHA-256 hashes of known malicious files placed by attackers; administrators should run integrity checks against these IoCs before concluding they are clean.

🎓 For beginners: FortiMail is a server that handles email for organizations. This bug is like a delivery person exploiting a confusing building address system to leave a package in the server room instead of the mailroom — except the "package" is a hacker's remote control script. Once placed, the script lets attackers run commands on the mail server at any time without logging in, even after the building changes the lock on the front door.

💡 Today I Learned: Mark-of-the-Web (MotW) ▶
Mark-of-the-Web is a Windows security mechanism that attaches a hidden Zone Identifier tag to files downloaded from the internet — this metadata tells Windows apps like Office or PowerShell that the file came from an untrusted source, triggering Protected View, SmartScreen warnings, and script execution blocks. The tag lives inside the file's NTFS alternate data streams and is checked by the operating system every time the file is opened, but notably it does not survive being copied to FAT32 drives or most ZIP extraction processes. Bypassing MotW is a critical attacker goal because it silences nearly all of Windows' user-facing security warnings, allowing malicious scripts and executables to run as if they were locally created, trusted files — which is exactly what CVE-2026-96951 exploits in today's Patch Tuesday.
📖 Glossary: MotW · SAML · WDAC · RaaS ▶
MotW — Mark-of-the-Web; a Windows NTFS alternate data stream tag automatically applied to internet-downloaded files that triggers enhanced security warnings and execution restrictions when those files are opened.
SAML — Security Assertion Markup Language; an XML-based open standard for exchanging authentication and authorization data between an identity provider (e.g., your company's login server) and a service provider (e.g., a SaaS app), enabling single sign-on across services.
WDAC — Windows Defender Application Control; a Windows security feature that allows administrators to define policies restricting which applications and scripts are permitted to run, preventing unauthorized software execution even with administrator credentials.
RaaS — Ransomware-as-a-Service; a criminal business model where ransomware developers build and maintain malware infrastructure, then lease it to "affiliates" who conduct attacks in exchange for a cut of ransom payments — similar to a software franchise, but for cybercrime.
