Critical FortiMail Zero-Day (CVE-2026-104286) Exploited — Unauthenticated Arbitrary File Write
🔍 What happened: Fortinet disclosed a CVSS 9.8 zero-day in FortiMail's IBE GUI component that lets unauthenticated attackers write files anywhere on the appliance via a path traversal and null byte bypass in crafted HTTP/HTTPS requests.
👤 Who's affected: Organizations running FortiMail 8.0.0–8.0.1, 7.6.0–7.6.6, 7.4.0–7.4.8, or 7.2.0–7.2.9 as their enterprise email security gateway.
✅ What to do: Upgrade to a patched FortiMail version immediately; if patching is delayed, restrict access to the FortiMail management interface from untrusted networks and monitor for unexpected new files on the appliance.
🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
Attackers send crafted HTTP/HTTPS requests to FortiMail's publicly accessible IBE GUI component, exploiting path traversal and null byte handling to write arbitrary files — establishing a foothold without credentials on a perimeter-facing email security appliance.
▶ Full analysis & beginner explanation
CVE-2026-104286 combines two weaknesses in FortiMail's Identity-Based Encryption GUI: improper path traversal handling and improper null byte neutralization. Together, they allow an attacker to craft an HTTP or HTTPS request that convinces the server to write controlled content to any path on the filesystem — bypassing the directory restriction meant to confine uploaded files to a safe location. No authentication is required; only network access to the HTTPS interface is needed to trigger the write.

Once arbitrary file-write is achieved, the typical follow-on is planting a web shell in a web-accessible directory, converting the write primitive into persistent interactive remote code execution. Fortinet confirmed active exploitation before issuing the patch — a true zero-day. CISA added CVE-2026-104286 to its Known Exploited Vulnerabilities catalog immediately, mandating U.S. federal agencies remediate by October 4, 2026. Patches are available for all affected branches.
🎓 For beginners: FortiMail is an email security appliance that filters spam and malware before it reaches a company's inbox. This bug is like a flaw in a building's mail-room scanner: instead of keeping deliveries contained, it lets anyone drop a package anywhere in the building — including the server room — without showing ID. That planted package can then unlock every door.

👤 Who's affected: Enterprises using NetScaler ADC or NetScaler Gateway configured as a SAML Service Provider (SP) or Identity Provider (IdP) for single sign-on.

🎯 ATT&CK: [Impact] T1499.004 · Endpoint Denial of Service: Application or System Exploitation
Attackers repeatedly crash NetScaler's SAML handler via the memory overflow — taking authentication infrastructure offline after six crashes trigger a full appliance reboot — while researchers also observe exploitation patterns consistent with remote code execution attempts.
▶ Full analysis & beginner explanation
CVE-2026-88779 is a memory overflow vulnerability in the SAML processing code of Citrix NetScaler ADC and NetScaler Gateway. When an appliance is configured for SAML-based authentication — common in enterprises using single sign-on — a specially crafted unauthenticated HTTP request can overflow a buffer in the SAML handler, crashing the service. Each exploit attempt crashes SAML; after six crashes, the entire appliance reboots, taking all dependent VPN and application authentication services offline.

While Citrix's official CVSS score of 8.7 reflects a denial-of-service classification, security researchers and network administrators monitoring active exploitation activity have observed behavior patterns consistent with remote code execution being attempted in some configurations — significantly elevating real-world risk beyond the DoS descriptor. The vulnerability was exploited as a zero-day before Citrix had a patch, and CISA added it to its KEV catalog on the same day as disclosure. Fixed versions (14.1-73.41 and 13.1-64.28) are available now.

Attackers Target Rejetto HFS Flaw (CVE-2026-61500) Enabling Admin Session Forgery and RCE
🔍 What happened: Attackers are actively exploiting a CVSS 9.3 flaw in Rejetto HTTP File Server 3.x where the server uses a non-cryptographic PRNG for session cookie signing keys and leaks enough PRNG output to unauthenticated clients to enable full key reconstruction and admin session forgery.
👤 Who's affected: Anyone running Rejetto HFS versions 3.0.0 through 3.2.0, commonly used for lightweight file sharing in small businesses, developer environments, and home labs.
✅ What to do: Upgrade to Rejetto HFS 3.2.1 or later immediately; if unable to patch, take HFS offline or restrict it to trusted internal networks only.
🎯 ATT&CK: [Credential Access] T1212 · Exploitation for Credential Access
Attackers observe login response data from HFS's Math.random() PRNG to reconstruct the generator's internal state, recover the session cookie signing key, and forge a valid administrator session cookie — using a cryptographic weakness to bypass authentication without any brute force.
▶ Full analysis & beginner explanation
CVE-2026-61500 exploits a fundamental cryptographic design error in Rejetto HFS 3.x: the server uses JavaScript's Math.random() — a non-cryptographic pseudorandom number generator — to generate the secret key used to sign session cookies. Math.random() is deterministic and seeded from a predictable source, and HFS inadvertently exposes enough PRNG output in its unauthenticated login responses for an attacker to reconstruct the generator's full internal state and thereby recover the signing secret.

Armed with the recovered signing key, the attacker forges a session cookie that the server accepts as a valid administrator session. Full admin access then enables exploitation of HFS's built-in server_code execution feature — which allows running arbitrary scripts on the host — achieving remote code execution. The entire kill chain requires only unauthenticated HTTP access to a publicly reachable HFS instance; no brute force, no credentials, no prior access. Rejetto HFS 3.2.1 replaces Math.random() with a cryptographically secure generator; upgrading is the only complete fix.
🎓 For beginners: Imagine a safe whose combination is generated by rolling ordinary dice, and the safe's door displays each dice roll on a small screen. After watching it long enough, you can predict the next roll and open the safe. That's exactly this flaw — HFS's "random" numbers aren't truly random, and the server accidentally shows enough of them for an attacker to figure out the secret key and gain full control.
CVE-2026-61500 · CVSS: 9.3/10 — Unauthenticated PRNG state reconstruction enables session cookie forgery and full RCE via built-in server_code feature; actively exploited in the wild.

💡 Today I Learned: Prompt Injection in AI Gateways ▶
Prompt injection is a class of attack where malicious instructions are embedded in data processed by an AI model, tricking it into executing unintended actions — in an AI coding assistant or gateway, this can escalate from generating bad suggestions to running OS commands on the host. When AI gateways like GitLab's process user-supplied template configurations, insufficient input neutralization creates a direct path from crafted prompt content to host-level command execution, turning a developer productivity tool into a remote shell. Defending against prompt injection requires strict input/output sanitization at every boundary, sandboxing AI processing components away from privileged system calls, and treating all AI-processed text as untrusted data that must be validated before any action is taken on it.
📖 Glossary: PRNG · Sandbox Escape · Session Cookie · Memory Overflow ▶
PRNG — Pseudorandom Number Generator: a deterministic algorithm that produces number sequences appearing random but predictable from a known seed; using a non-cryptographic PRNG (like Math.random()) for security-critical values such as session signing keys is dangerous because an attacker who observes enough outputs can reconstruct the internal state and derive the secret.
Sandbox Escape — A vulnerability allowing code executing inside an isolated environment designed to contain dangerous operations to break out and interact with the host system or broader network, bypassing the security boundary the sandbox was built to enforce.
Session Cookie — A browser-stored token signed by the server that proves an authenticated user's identity for the duration of a session; if the signing key is weak, predictable, or leaked, an attacker can forge a cookie to impersonate any user — including an administrator — without knowing their password.
Memory Overflow — A condition where a program writes more data into a fixed-size buffer than it can hold, corrupting adjacent memory; in a network-facing service, a remotely triggered overflow can overwrite program control structures and redirect execution, allowing attackers to run arbitrary commands on the target.
