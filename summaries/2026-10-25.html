PHP "PHP2Shell" RCE Flaws Actively Exploited — Patch All Web Servers Now (CVE-2026-109618, CVE-2026-109619)
🔍 What happened: PHP shipped emergency patches for two critical unauthenticated RCE vulnerabilities dubbed "PHP2Shell" that allow attackers to execute arbitrary code before any application security controls run.
👤 Who's affected: Every web server running mod_php, PHP-FPM, php-cgi, FrankenPHP, or LiteSpeed on PHP versions prior to 8.2.35, 8.3.36, 8.4.27, or 8.5.12 — effectively all WordPress, Laravel, Drupal, and Symfony sites not yet patched.
✅ What to do: Update PHP immediately to 8.2.35, 8.3.36, 8.4.27, or 8.5.12; PHP 8.1 and older users must apply vendor-backported patches or isolate the system; deploy Fastly's WAF virtual patch as a temporary safeguard.
🎯 ATT&CK: [Initial Access] T1190 · Exploit Public-Facing Application
Attackers send malformed HTTP requests that trigger PHP memory corruption before any application code executes, achieving unauthenticated shell access on any vulnerable web server directly reachable from the internet.
▶ Full analysis & beginner explanation

The PHP2Shell flaws stem from how PHP handles memory when an HTTP request ends abnormally. CVE-2026-109618 creates an out-of-memory condition that corrupts the interpreter's internal state, while CVE-2026-109619 exploits stale global state after request teardown—a classic use-after-free scenario where PHP continues referencing memory it has already released.

The PHP security team rates mod_php (PHP as an Apache module) the highest-risk deployment. Demonstrated exploits trigger execution before any application-level authentication checks, meaning a fully updated WordPress installation with strong passwords remains trivially exploitable if PHP itself is unpatched. Exploitation was first confirmed in watchTowr's honeypot network; Amazon's threat intelligence team traced attack attempts back to October 17. Fixed versions exist for PHP 8.2–8.5; users on PHP 8.1 or older should urgently contact their distribution or hosting provider for backported patches since those branches no longer receive regular updates.

🎓 For beginners: PHP is the programming language that runs most of the web—WordPress, online stores, news sites. These bugs exist in PHP itself, not in any website's code. A hacker can send a specially crafted message to any unpatched website and take full control of its server, no password required. It's like discovering a skeleton key that opens any door built by the same manufacturer.
CVE-2026-109618 & CVE-2026-109619 · CVSS v4.0: 9.2/10 — Critical severity; unauthenticated network-exploitable RCE with high impact on confidentiality, integrity, and availability.

💡 Today I Learned: Use-After-Free ▶
A use-after-free (UAF) vulnerability occurs when a program frees (releases) a block of memory but retains a pointer that still references that freed location—and then uses that pointer again later when the memory may have been reallocated for something else entirely. This is exactly the mechanism behind CVE-2026-109619 (one of the PHP2Shell flaws): PHP frees request-scoped memory at the end of an HTTP request but leaves a stale global pointer referencing it; an attacker who can control what data fills that freed memory slot can redirect PHP's execution flow to run attacker-supplied code. UAF vulnerabilities are especially dangerous because modern memory allocators are often predictable enough that attackers can reliably control what data lands in the freed slot, turning a seemingly random crash into a reliable exploit.
📖 Glossary: APT · PyPI · UAF · mod_php · SQL Injection · Credential Stealer ▶
APT — Advanced Persistent Threat; a sophisticated, often state-sponsored hacking group that conducts long-term, targeted intrusion campaigns against specific organizations, prioritizing stealth and persistence over speed.
PyPI — Python Package Index; the official public repository where Python developers publish and download software packages; a major supply chain attack surface because packages are trusted and often auto-updated.
UAF — Use-After-Free; a memory corruption vulnerability where a program accesses a freed memory region, allowing attackers who control what fills that region to hijack program execution.
mod_php — A PHP execution mode where PHP runs as a module inside the Apache web server process; the fastest and most common way to serve PHP websites, and the highest-risk deployment for the PHP2Shell RCE flaws.
SQL Injection — A web attack technique where malicious database query code is inserted into an application's input fields, enabling attackers to read, modify, delete, or exfiltrate database contents without authorization.
Credential Stealer — Malware specifically designed to locate and exfiltrate stored usernames, passwords, API keys, and authentication tokens from a compromised system or environment.
