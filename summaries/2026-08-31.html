Berlin Refuses to Pay Hackers Who Stole 5.79 TB From State Network

Rhysida simultaneously encrypted Berlin's administrative network and exfiltrated 5.79 TB of sensitive government files, using the dual-pressure of locked operations and threatened data auction to coerce a ransom payment ahead of German elections.
▶ Full analysis & beginner explanation

The Rhysida ransomware group posted a claim on its dark web leak site on August 28 alleging a major breach of Berlin's state government IT network. Forensic investigation confirmed data exfiltration occurred between August 7 and August 12 — a five-week dwell period before detection. The 5.79 TB haul includes approximately 1.44 million files: 80,000 administrative fine proceedings, 46,500 contracts, nearly 6,000 files containing login credentials, emergency response plans, and sensitive judicial records.

The political timing is significant. Germany faces federal elections in autumn 2026, and the stolen data includes operational details about Berlin's public safety and mobility infrastructure. Rhysida is demanding 30 bitcoin and has set a one-week countdown before auctioning the data — a tactic designed to maximize psychological pressure. Notably, Rhysida has not published any data samples yet, suggesting active negotiations may be ongoing behind the scenes despite the government's public refusal.

"The state of Berlin will not submit to extortion," declared Mayor Kai Wegner and Interior Senator Iris Spranger in a joint statement. This is the correct response — paying ransoms rarely guarantees data deletion and directly funds future attacks. However, the risk of mass exposure of personal data and infrastructure details remains real and immediate if Rhysida follows through on its threat.

APT Exploits VMware vCenter CVE-2026-59310 to Deploy Backdoors and Ransomware Across 361 Victims in 47 Countries

👤 Who's affected: Organizations running unpatched VMware vCenter across 47 countries — confirmed victims span energy companies, defense contractors, healthcare systems, and government agencies.
✅ What to do: Apply Broadcom's patches immediately; hunt for malicious cron jobs and reverse_ssh binaries in your vCenter environment; disable internet-facing vCenter management interfaces if patching is delayed; review logs for path traversal patterns (/../ sequences) beginning August 3.

▶ Full analysis & beginner explanation

CVE-2026-59310 is a path traversal vulnerability in VMware vCenter that allows unauthenticated attackers to read and write arbitrary files outside the intended web root. Researchers at German firm Quirso discovered active exploitation during an incident response engagement, finding the first compromised systems had contacted attacker infrastructure on August 3 — just five days after Broadcom published the advisory on July 29.

The attack chain is methodical: initial exploitation via specially crafted HTTP requests achieves RCE, then a malicious cron job is installed as a persistence mechanism, after which the open-source reverse_ssh tool establishes an encrypted SSH tunnel back to attacker-controlled infrastructure. In several investigated cases, attackers then pivoted to deploy a modified Babuk ransomware variant — suggesting either financial motivation or deliberate false-flag operations designed to obscure espionage objectives behind ransomware noise.

Quirso attributed the campaign with moderate confidence to a China-nexus APT based on tooling overlaps and the target profile: energy companies, defense contractors, healthcare, and government — consistent with Chinese state-sponsored intelligence collection priorities. The 361 victim IPs span 47 countries, indicating an automated, opportunistic scanning campaign rather than highly targeted intrusions.

🎓 For beginners: VMware vCenter is the software IT administrators use to manage hundreds or thousands of virtual servers at once — it's the master control panel for entire data centers. A flaw in vCenter doesn't just affect one machine; it can compromise every server the data center manages. This vulnerability let attackers walk in without a password, install a "cron job" (a scheduled automated task) to keep the door open permanently, and tunnel out through an encrypted connection disguised as normal network traffic.

Cosmos EVM Integer Underflow Exploit Drains $5.7M From Six Blockchains After Cosmos Labs Botched the Disclosure
🔍 What happened: An attacker exploited a critical integer underflow vulnerability in the shared Cosmos EVM module (known since April 2026 but misclassified as low-risk) to generate unlimited token balances and drain approximately $5.7 million across six blockchain networks between August 20–25, 2026.

🎯 ATT&CK: [Impact] T1657 · Financial Theft
The attacker weaponized the integer underflow to generate token balances of effectively 2^256−1 base units (a 78-digit number), then liquidated these artificially inflated tokens to drain approximately $5.7 million in real value across six blockchain networks in a five-day coordinated campaign.
▶ Full analysis & beginner explanation

This is a textbook case of how poor vulnerability triage can transform a known bug into a catastrophic exploit. The integer underflow was reported through Cosmos Labs' bug bounty program on April 25, 2026, but the security team incorrectly assessed it as "posing no risk to funds on live networks." The miscalculation: the bug was conditional on a specific decimal configuration that researchers initially thought limited its applicability. By August 13, internal analysis confirmed all Cosmos EVM chains were vulnerable regardless of decimal configuration — but the response remained a low-urgency "silent patch" rather than emergency coordinated disclosure.

The attack mechanism is elegant in its exploitation of integer arithmetic: by setting up an account holding locked tokens and delegating more tokens to a validator than the account balance allowed, the attacker caused the balance to underflow. Instead of the expected error, the system wrapped the value around to 2^256−1 — effectively giving the attacker an unlimited supply of tokens. They then liquidated these against real liquidity pools across six chains over five days, netting approximately $5.7 million before the patch could stop them.

The disclosure failure is arguably worse than the technical flaw. Cosmos Labs coordinated with 40 chains during response but only 13 had patched or halted before exploitation began. The silent patching approach — routing fixes through a public code repository without urgent operator notification — gave no urgency signal to the 27 chains that were ultimately attacked.

🎓 For beginners: Imagine a bank where the software controlling balances has a math bug: if you have $0 and try to spend $1, instead of declining the transaction, the balance "wraps around" like an odometer rolling past 99999 back to 00000 — except it goes to the maximum possible number (trillions of dollars). The tragedy here is that the bug was reported four months earlier but dismissed as safe.

Five Critical WordPress Plugin and Theme Flaws Enable Site Takeover or Remote Code Execution
🔍 What happened: Researchers disclosed five critical vulnerabilities across widely-used WordPress plugins and themes, headlined by a CVSS 9.8 HMAC signing oracle authentication bypass in WPMU DEV Dashboard (350,000+ active installs, CVE-2026-76581) that allows unauthenticated attackers to gain WordPress administrator access.
👤 Who's affected: WordPress site owners running WPMU DEV Dashboard ≤ 5.0.1 with Hub SSO enabled — approximately 350,000 sites — plus sites running vulnerable versions of Avada theme (CVE-2026-18431, arbitrary file write enabling PHP RCE).
✅ What to do: Update WPMU DEV Dashboard to version 5.0.2 (released August 24); update Avada theme to the latest patched version; disable Hub SSO temporarily if immediate patching isn't possible; audit administrator accounts for any unauthorized additions.
🎯 ATT&CK: [Privilege Escalation] T1078 · Valid Accounts
The HMAC signing oracle flaw in WPMU DEV Dashboard allows attackers to forge a valid authentication token and replay it to obtain a session with administrator-level privileges — effectively impersonating a site administrator without knowing any actual credentials.
▶ Full analysis & beginner explanation

The critical flaw in WPMU DEV Dashboard (CVE-2026-76581, CVSS 9.8) stems from an inconsistency in how the plugin constructs and validates HMAC-SHA-256 signatures during the Hub SSO authentication process. The vulnerability functions as a "signing oracle": the unauthenticated first-stage endpoint produces a valid HMAC that can be replayed in a completely different logical context. Anti-replay controls don't prevent the attack because the attacker receives a fresh token during the exploit flow itself. The result: any unauthenticated visitor can claim administrator-level access to a vulnerable WordPress site.

Among the other four critical flaws, CVE-2026-18431 in the Avada theme is particularly dangerous: it allows unauthenticated arbitrary file write to the web server, meaning attackers can upload PHP files and execute arbitrary code server-side. The three additional vulnerabilities round out a pattern of input validation failures across widely-deployed WordPress ecosystem components.

🎓 For beginners: Think of HMAC as the wax seal on a medieval letter — it proves the message came from a trusted sender without revealing the king's secret seal design. This vulnerability is like a forged seal: the plugin accidentally revealed enough information for anyone to create their own "official" seal and walk right into the castle as an administrator. With 350,000 WordPress sites at risk, attackers often automate these attacks — scanning the entire internet for vulnerable sites within hours of public disclosure.

💡 Today I Learned: Integer Underflow ▶
An integer underflow is a software bug where a number decreases below its minimum representable value — typically zero for an unsigned integer — causing it to "wrap around" to the largest possible value instead of triggering an error. In the Cosmos EVM exploit, an attacker triggered this by delegating more locked tokens to a validator than an account actually held, causing the balance to underflow from zero to 2^256−1: a number with 78 digits, effectively infinite spending power. The root cause is that many programming environments don't automatically check whether arithmetic operations produce valid results, making integer overflow/underflow bugs one of the most persistent and costly vulnerability classes in financial software.
📖 Glossary: EVM · KEV · GraphQL · RaaS · Double Extortion · SNMP · Directory Traversal · HMAC ▶
EVM — Ethereum Virtual Machine; the sandboxed runtime environment that executes smart contract code across Ethereum and compatible blockchains like Cosmos chains.
KEV — Known Exploited Vulnerabilities; CISA's authoritative catalog of security flaws confirmed to be actively exploited in the wild, used to mandate federal patching timelines.
GraphQL — An API query language that lets clients request exactly the data fields they need; injection vulnerabilities in GraphQL handlers can lead to unauthorized data exposure or remote code execution.
RaaS — Ransomware-as-a-Service; a criminal business model where ransomware developers lease their attack tools to affiliates who execute campaigns and split the ransom proceeds, lowering the technical barrier for attackers.
Double Extortion — A ransomware tactic that combines encrypting the victim's data with exfiltrating a copy first, threatening to publicly release or sell the stolen data to create additional pressure beyond just restoring access.
SNMP — Simple Network Management Protocol; used to monitor and manage network devices and servers; misconfigurations or command-injection flaws in SNMP handlers can allow unauthenticated remote command execution, as seen in Zimbra CVE-2026-73570.
Directory Traversal — A web attack technique that manipulates file path references using sequences like "../" to access files and directories outside the web server's intended root, as exploited in CVE-2026-59310 against VMware vCenter.
HMAC — Hash-based Message Authentication Code; a cryptographic construct that verifies a message came from a trusted sender using a shared secret key; vulnerabilities that expose a signing oracle can allow attackers to forge valid HMACs and bypass authentication.
