Hackers Exploit Critical Nextcloud RCE Flaw (CVE-2026-110447, CVSS 9.2) to Backdoor Servers
🔍 What happened: Threat actors are actively exploiting a critical command injection flaw (CVE-2026-110447, CVSS 9.2) in the Collabora Online Built-in CODE Server app for Nextcloud, enabling unauthenticated remote code execution and persistent backdoor installation.
👤 Who's affected: Organizations running Nextcloud with the Collabora Online Built-in CODE Server integration enabled — commonly deployed in government agencies, healthcare systems, and enterprises as a privacy-respecting alternative to Google Workspace.
✅ What to do: Immediately update the Collabora Online Built-in CODE Server app in the Nextcloud App Store; audit server logs, all admin accounts, and writable web directories for web shell artifacts or unauthorized accounts.
🎯 ATT&CK: [Persistence] T1505 · Server Software Component
After exploiting the RCE flaw, attackers install persistent web shells and backdoors within the Nextcloud server environment, maintaining access even after the initial vulnerability is patched if not actively hunted.
▶ Full analysis & beginner explanation

The Collabora Online Built-in CODE Server is a document collaboration engine bundled with many enterprise Nextcloud deployments, letting users open and edit office documents directly in their browsers. CVE-2026-110447 is a command injection flaw rated CVSS 9.2 — an unauthenticated attacker who can reach the Collabora service over the network can send a specially crafted request that triggers arbitrary OS command execution with the privileges of the Nextcloud web server process. Active exploitation was confirmed on October 19, with incident responders observing attackers installing persistent backdoors on vulnerable servers shortly after initial access.

The attack pattern follows a well-documented post-exploitation playbook: initial RCE is leveraged to create hidden administrative accounts, deploy web shells in writable directories, or modify server-side code to introduce backdoors that survive reboots and patching attempts if not proactively removed. Nextcloud is widely deployed in sectors that handle sensitive data — government agencies, healthcare, legal, and research institutions — making this target pool particularly high-value for threat actors seeking persistent footholds.

Mitigation is available: administrators should immediately update the Collabora Online Built-in CODE Server through the Nextcloud App Store. Beyond patching, a thorough forensic review is warranted — admins should audit all active user and admin accounts for unauthorized entries, check scheduled tasks and startup scripts for modifications, and scan writable web directories for unexpected PHP files that may represent dropped web shells.

🎓 For beginners: Nextcloud is like your own private Google Drive hosted on your own servers. The Collabora Online app is the built-in document editor — think Google Docs running on your hardware. A hacker found a flaw that lets them send a special request to the server and trick it into running their commands without a password. Once inside, they're planting hidden "back doors" — secret entry points that let them return even after the original flaw is fixed.

ConnectWise SkyKick OAuth Credential Stolen — ~1,000 Microsoft 365 Tenants Exposed, 173 Confirmed Breached
🔍 What happened: An attacker stole a ConnectWise Cloud Backup (formerly SkyKick) OAuth application credential and used it to silently authenticate into Microsoft 365 tenants without triggering MFA, with 173 confirmed breaches and sign-in activity visible in roughly 1,000 tenants.
👤 Who's affected: Organizations using ConnectWise Cloud Backup for Microsoft 365 — primarily managed service providers and their customers; in at least one tenant, the attacker escalated to Global Administrator and added new persistent OAuth secrets.
✅ What to do: Immediately disable (do not delete) the ConnectWise Cloud Backup/SkyKick application in your Microsoft Entra admin center and audit Entra ID for new Global Administrator role assignments and unauthorized app client secret additions.
🎯 ATT&CK: [Credential Access] T1528 · Steal Application Access Token
The attacker used a stolen OAuth client credential — a client assertion or client secret — to authenticate as the ConnectWise backup application itself across customer tenants, bypassing MFA entirely since the sign-in appeared to come from a trusted application identity rather than a human user.
▶ Full analysis & beginner explanation

ConnectWise Cloud Backup, formerly SkyKick, is a Microsoft 365 backup-as-a-service solution widely used by managed service providers. The product works by registering an Enterprise Application in each customer's Microsoft Entra ID tenant, granting it delegated permissions to read and back up mailboxes, SharePoint sites, and Teams content. A threat actor obtained one of ConnectWise's backend OAuth application credentials — either a client secret or a signed JWT client assertion — and used it to silently authenticate as the ConnectWise application across customer tenants. Because the sign-in originated from a trusted application identity rather than a user account, Microsoft's MFA policies never engaged.

Huntress identified the breach starting October 15 and tracked unauthorized sign-ins across at least 162 Microsoft 365 tenants initially, rising to 173 confirmed by October 17. By October 19, sign-in activity from the attacker's IP ranges was visible in approximately 1,000 tenants. In at least one case, the attacker used the app's delegated permissions to add itself to the Global Administrator role in an Entra ID directory and created new client secrets on trusted applications — establishing additional persistence pathways that survive the original credential's revocation.

This is a textbook supply-chain attack via MSP tooling: a single vendor credential compromise cascades to hundreds of downstream organizations simultaneously. ConnectWise has revoked the affected credential and shut down the Cloud Backup service; data restores are unavailable while the investigation continues. Responders advise disabling (not deleting) the affected applications to preserve forensic evidence, and recommend hunting for Entra ID backdoors — specifically unexpected Global Administrator assignments and newly added OAuth app secrets — that may provide ongoing attacker access.

🎓 For beginners: Managed Service Providers are IT companies that manage technology for other businesses. ConnectWise makes a backup tool that MSPs use to protect client Microsoft email and files. Think of it as a master key card that opens hundreds of office buildings — one card, many doors. A hacker stole ConnectWise's master key card (called an OAuth token). They walked into hundreds of Microsoft 365 tenants without triggering any password prompts or phone verification, and in some buildings even promoted themselves to "building owner" before leaving.
No specific CVE · OAuth application credential theft — The stolen token bypassed multi-factor authentication entirely because it authenticated as the application itself, not as a human user.

💡 Today I Learned: OAuth Application Tokens ▶
OAuth Application Tokens are machine-to-machine credentials that allow one software service to authenticate to another without any human involvement — they are how a backup tool signs into Microsoft 365 on your behalf using a client secret or cryptographic assertion rather than a username and password. Unlike user logins, these tokens typically cannot be blocked by multi-factor authentication because no human is logging in: the application presents a pre-issued credential and the identity platform grants access based on that credential alone. When attackers steal an OAuth app token, they inherit every permission the application was granted across every tenant or customer where it is installed — potentially bypassing MFA for thousands of organisations simultaneously, as demonstrated in the ConnectWise SkyKick incident this week.
📖 Glossary: OAuth · MFA · Entra ID · WAF · DoS ▶
OAuth — An open standard authorisation protocol that allows one service to access another service's resources on behalf of a user or application using short-lived tokens instead of passwords.
MFA (Multi-Factor Authentication) — A security mechanism requiring two or more independent verification methods — such as a password plus a phone-generated code or biometric — before granting access to a system.
Entra ID — Microsoft's cloud-based identity and access management service (formerly Azure Active Directory) that controls logins, permissions, and application registrations for Microsoft 365 and Azure environments.
WAF (Web Application Firewall) — A security appliance or cloud service that filters and monitors HTTP/S traffic between the internet and a web application, blocking common attacks like SQL injection, cross-site scripting, and command injection.
DoS (Denial of Service) — An attack that overwhelms a system, server, or network with traffic or malformed requests to exhaust its resources and make it unavailable to legitimate users.
